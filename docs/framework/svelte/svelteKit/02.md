# 二、`src/routes`目录 

## 2.1 路由 

### 2.1.1 路由类型

| 文件路径 | 对应 URL | 说明 |
|--------|--------|------|
| `src/routes/+page.svelte` | `/` | 根页面 |
| `src/routes/about/+page.svelte` | `/about` | 静态路由 |
| `src/routes/blog/[slug]/+page.svelte` | `/blog/hello` | 动态参数（`slug = 'hello'`）|
| `src/routes/blog/[...rest]/+page.svelte` | `/blog/a/b/c` | Rest 参数（`rest = 'a/b/c'`）|

### 2.1.2 路由跳转


1. 使用 `<a>`标签（推荐）

    ```svelte
    <!-- 基本跳转 -->
    <a href="/about">关于我们</a>
    <a href="/blog/hello-world">查看文章</a>

    <!-- 新标签页打开 -->
    <a href="/external" target="_blank" rel="noopener">外部链接</a>
    ```

2. 使用 `goto`函数（编程式导航）

    ```svelte
    <script>
      import { goto } from '$app/navigation';
      import { page } from '$app/stores';

      // 基本跳转
      function navigateToAbout() {
        goto('/about');
      }

      // 带参数跳转
      function navigateToPost() {
        goto('/blog/sveltekit-tutorial');
      }

      // 带选项的跳转
      function navigateWithOptions() {
        goto('/dashboard', {
          replaceState: true,      // 替换历史记录
          noScroll: true,         // 不滚动到顶部
          keepFocus: true,        // 保持焦点
          state: { from: 'home' } // 状态数据
        });
      }

      // 获取当前路由信息
      console.log($page.url.pathname);  // 当前路径
      console.log($page.url.search);    // 查询参数
    </script>

    <button on:click={navigateToAbout}>跳转到关于页面</button>
    ```

3. 使用 `redirect`重定向

    ```javascript
    // src/routes/+page.server.js
    export function load() {
      throw redirect(307, '/dashboard');
      // 或
      return { status: 307, redirect: '/dashboard' };
    }
    ```

### 2.1.3 路由参数


1. 单参数路由

    ```svelte
    <!-- src/routes/blog/[slug]/+page.svelte -->
    <script>
      import { page } from '$app/stores';
    
      // 获取路由参数
      const { slug } = $page.params;
    </script>

    <h1>文章: {slug}</h1>
    ```

2. 多参数路由

    ```svelte
    <!-- src/routes/user/[userId]/post/[postId]/+page.svelte -->
    <script>
      import { page } from '$app/stores';
    
      const { userId, postId } = $page.params;
    </script>

    <p>用户 {userId} 的文章 {postId}</p>
    ```

3. 路由参数验证

    ```javascript
    // src/routes/blog/[slug]/+page.server.js
    export function load({ params }) {
      // 参数验证
      if (!params.slug || params.slug.length < 3) {
        throw error(404, '文章不存在');
      }
    
      return {
        slug: params.slug
      };
    }
    ```

## 2.2 布局

### 2.2.1 根布局

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  // Svelte 5 写法：使用 Runes
  let { data } = $props(); // 接收 layout data
</script>

<header>
  <nav>My App</nav>
</header>

<slot /> <!-- 子页面内容 -->

<footer>© 2026</footer>
```

>  所有页面都会包裹在此布局中。


### 2.2.2 嵌套路由与嵌套布局

```text
src/routes/
├── +layout.svelte          # 根布局
├── +page.svelte            # 首页
├── about/
│   └── +page.svelte        # /about
└── dashboard/
    ├── +layout.svelte      # 仅 dashboard 子路由生效
    ├── +page.svelte        # /dashboard
    └── settings/
        └── +page.svelte    # /dashboard/settings
```

*   访问 `/dashboard` → 同时应用 **根布局 + dashboard 布局**
*   `<slot />` 在 `dashboard/+layout.svelte` 中渲染 `/dashboard` 或 `/dashboard/settings` 的内容


### 2.2.3 分组布局（避免 URL 污染）

```txt
src/routes/
└── (marketing)/
    ├── +layout.svelte   # 仅用于 /, /about, /contact
    ├── +page.svelte
    └── about/+page.svelte
└── (app)/
    ├── +layout.svelte   # 仅用于 /app, /app/profile
    └── app/
        └── profile/+page.svelte
```

> 目录名用 `(...)` 包裹表示 **逻辑分组，不生成 URL 路径**。


## 2.3 单文件夹内容

### 2.3.1 文件内容

1. 目录结构

    ```txt
    src/routes/xxx/
    ├── +page.js   
    ├── +page.server.js
    └── +page.svelte
    ```
2. 执行顺序

    ```txt
    用户请求页面
        ↓
    +page.server.js (如果存在)
        ↓ → load() 只在服务器运行
    +page.js (如果存在)
        ↓ → load() 在服务器和客户端都可能运行
    +page.svelte
        ↓ → 接收 data 并渲染
    ```

3.  +page.server.js 与 +page.js 的区别

    | 特性 | `+page.server.js` | `+page.js` |
    |------|------------------|-----------|
    | 运行位置 | 仅服务端（Node.js / Edge） | 服务端 + 客户端 |
    | 能否访问敏感信息 | 可访问 `cookies`, `headers`, `env`, 数据库等 | 不能（客户端无权限） |
    | 是否参与 SSR |  是（直接注入 HTML） | 是（但数据需可序列化） |
    | 是否在客户端导航时运行 | 否（仅首次请求） | 是（每次路由跳转都运行） |
    | 安全性 | 高（代码不暴露给前端） | 低（代码打包到前端） |
    | 典型用途 | 用户认证、数据库查询、私有 API 调用 | 组合数据、声明依赖、轻量逻辑 |

4. 决策树：如何选择？

    ```txt
    开始
      │
      ├─ 需要访问数据库/文件系统？
      │   ├─ 是 → 使用 +page.server.js
      │   └─ 否 ↓
      │
      ├─ 需要读取 cookies/headers？
      │   ├─ 是 → 使用 +page.server.js
      │   └─ 否 ↓
      │
      ├─ 需要环境变量/密钥？
      │   ├─ 是 → 使用 +page.server.js
      │   └─ 否 ↓
      │
      ├─ 需要服务器端重定向？
      │   ├─ 是 → 使用 +page.server.js
      │   └─ 否 ↓
      │
      ├─ 需要表单处理？
      │   ├─ 涉及敏感操作 → 使用 +page.server.js
      │   └─ 公开表单 → 使用 +page.js
      │
      └─ 其他情况 → 使用 +page.js
    ```

### 2.3.2 `+page.server.js`与`+page.js`

1. `+page.server.js`

    ```js
    // src/routes/profile/+page.server.js
    export async function load({ cookies, request, platform }) {
      // 可安全读取 Cookie
      const session = cookies.get('session');
    
      // 可调用内部服务（不暴露 API）
      const user = await db.getUserBySession(session);
    
      // 可访问环境变量（如 DB_URL）
      console.log(import.meta.env.DB_URL); // 安全！不会泄露到前端
    
      return { user };
    }
    ```

    - 只在服务端运行（构建时或请求时）
    - 代码永远不会发送到浏览器
    - 适合处理敏感操作

2. `+page.js`

    ```js
    // src/routes/profile/+page.js
    export async function load({ data, url, depends }) {
      // 无法访问 cookies / headers
      // 无法访问数据库或私有 env
    
      // 可访问父级 layout 的 data
      const parentData = await parent();
    
      // 可声明依赖（用于手动刷新）
      depends('app:user-preferences');
    
      // 可调用公开 API
      const prefs = await fetch('/api/user-prefs').then(r => r.json());
    
      return { ...data, preferences: prefs };
    }
    ```

    - 在服务端（SSR）和客户端（CSR 导航）都会运行
    - 代码会被打包进前端 bundle
    - 只能处理公开、非敏感逻辑

### 2.3.3 表单提交

1. 在 `+page.server.js` 中定义动作


    ```js
    // src/routes/login/+page.server.js
    import { fail, redirect } from '@sveltejs/kit';
    import { loginUser } from '$lib/server/auth';

    export const actions = {
      // 默认动作（对应 <form method="POST">）
      default: async ({ request, cookies }) => {
        const formData = await request.formData();
        const email = formData.get('email');
        const password = formData.get('password');

        // 验证输入
        if (!email || !password) {
          return fail(400, { email, missingFields: true });
        }

        // 业务逻辑（如登录）
        const user = await loginUser(email, password);
        if (!user) {
          return fail(401, { email, invalidCredentials: true });
        }

        // 设置 Cookie / Session
        cookies.set('session', user.sessionToken, { httpOnly: true });

        // 成功后重定向（防止重复提交）
        throw redirect(303, '/dashboard');
      },

      // 命名动作（对应 <form method="POST" action="?/logout">）
      logout: async ({ cookies }) => {
        cookies.delete('session');
        throw redirect(303, '/');
      }
    };
    ```

    > `actions` 是一个对象，键名即动作名：
    > 
    > *   `default` → 无 `action` 属性的 `<form>`
    > *   `logout` → `<form action="?/logout">`


2. 在页面中使用表单（`+page.svelte`）

    ```svelte
    <!-- src/routes/login/+page.svelte -->
    <script>
      import { enhance } from '$app/forms';
      let { form } = $props(); // 接收上一次提交的数据（用于回显/错误）
    </script>

    <form method="POST" use:enhance>
      <label>
        Email:
        <input
          name="email"
          type="email"
          value={form?.email ?? ''}
          aria-invalid={form?.missingFields}
        />
      </label>

      {#if form?.missingFields}
        <p class="error">Email is required</p>
      {/if}

      {#if form?.invalidCredentials}
        <p class="error">Invalid email or password</p>
      {/if}

      <button type="submit">Login</button>
    </form>

    <!-- 命名动作示例：登出 -->
    <form method="POST" action="?/logout">
      <button type="submit">Logout</button>
    </form>
    ```

    > 关键点：
    > 
    > *   `use:enhance` → 启用客户端增强（SPA 式提交，无整页刷新）
    > *   `$props().form` → 自动接收 `fail()` 返回的数据（用于错误回显）


## 2.4 API调用

在 SvelteKit 中，src/routes/api/ 下的文件用于创建自定义 HTTP API 端点（类似传统后端的 REST 接口）。这些接口可通过 fetch() 从客户端或外部系统调用。

但要注意：SvelteKit 官方推荐优先使用 +page.server.js 的 load 和 actions，仅在必要时才创建 /api/ 路由（如提供给移动端、Webhook、或非表单交互）。


### 2.4.1 基本结构

每个 `+server.js` 文件导出 HTTP 方法函数（`GET`, `POST`, `PUT`, `DELETE` 等）：

```js
// src/routes/api/hello/+server.js
import { json } from '@sveltejs/kit';

export const GET = async () => {
    return json({ message: 'Hello from API!' });
};

export const POST = async ({ request }) => {
    const data = await request.json();
    return json({ received: data });
};
```

> 访问方式：
> 
> *   `GET /api/hello` → 返回 JSON
> *   `POST /api/hello` → 接收 JSON 并回显


### 2.4.2 请求上下文

所有方法接收一个 **`event` 对象**，包含：

| 属性  | 说明  |
| --- | --- |
| `request` | 原始 Request 对象 |
| `url` | URL 实例（含 searchParams） |
| `params` | 动态路由参数（如 `/api/users/[id]`） |
| `cookies` | Cookie 操作（`.get()`, `.set()`, `.delete()`） |
| `platform` | 部署平台信息（Vercel, Cloudflare 等） |
| `locals` | 来自 `hooks.server.js` 的共享数据（如用户会话） |

示例：带参数和认证的 API

```js
// src/routes/api/users/[id]/+server.js
import { json } from '@sveltejs/kit';

export const GET = async ({ params, locals }) => {
    const { id } = params;

    // 检查用户是否登录（假设 hooks.server.js 设置了 locals.user）
    if (!locals.user) {
        return json({ error: 'Unauthorized' }, { status: 401 });
    }

    const user = await db.getUserById(id);
    if (!user) {
        return json({ error: 'Not found' }, { status: 404 });
    }

    return json(user);
};
```


### 2.4.3 响应格式

1. **JSON 响应（最常用）**

    ```js
    import { json } from '@sveltejs/kit';
    return json({ success: true }, { status: 201 });
    ```

2. **纯文本 / HTML**

    ```js
    return new Response('OK', {
      headers: { 'Content-Type': 'text/plain' }
    });
    ```

3. **重定向**

    ```js
    throw redirect(303, '/login');
    // 或
    return new Response(null, {
      status: 303,
      headers: { Location: '/login' }
    });
    ```

4. **流式响应**

    ```js
    export const GET = () => {
      const stream = new ReadableStream({
        start(controller) {
          controller.enqueue('data: Hello\n\n');
          setTimeout(() => controller.close(), 1000);
        }
      });
      return new Response(stream, {
        headers: { 'Content-Type': 'text/event-stream' }
      });
    };
    ```
