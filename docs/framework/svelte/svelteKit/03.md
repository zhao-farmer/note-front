# 三、`src/lib` 目录 

在 **SvelteKit** 项目中，`src/lib/` 是一个**核心共享目录**，用于存放**可在整个应用中复用的代码和资源**。你列出的结构是社区广泛采用的最佳实践，下面详细说明每个子目录的作用和使用规范：

整体定位：`src/lib/` 是什么？

- **所有内容均可通过 `$lib` 别名导入**（如 `import { foo } from '$lib/utils/helpers'`）
- **既可用于服务端（`.server.` 文件），也可用于客户端（组件）**
- **不要放敏感逻辑**（敏感代码应放在 `src/lib/server/`）

## 3.1 组件

在 **SvelteKit** 项目中，`src/lib/components/` 是一个**约定优于配置**的目录，用于存放**可复用的 UI 组件**（如按钮、卡片、导航栏等）。它结合 SvelteKit 内置的 `$lib` 别名，提供简洁、高效、类型安全的组件组织方式。

### 3.1.1 目录结构与约定

```txt
src/
├── lib/
│   └── components/          ← 自定义 UI 组件
│       ├── Button.svelte
│       ├── Card.svelte
│       └── Header/
│           ├── Header.svelte
│           └── Header.test.js
├── routes/
│   └── +page.svelte         ← 页面中使用组件
└── app.html
```

>  虽然 `components/` 不是强制要求（你可以直接放 `src/lib/Button.svelte`），但**分组管理更清晰**，尤其项目变大时。

### 3.1.2 `$lib` 别名：关键特性

SvelteKit **自动配置 Vite**，将 `src/lib` 映射为 **`$lib`** 别名：

```svelte
<!-- 在任何 .svelte 或 .js/.ts 文件中 -->
<script>
  import Button from '$lib/components/Button.svelte';
  import Header from '$lib/components/Header/Header.svelte';
</script>
```

> 注意：`$lib` 指向 **`src/lib`**，不是 `src/lib/components`。  
> 所以完整路径是 `$lib/components/xxx.svelte`。


### 3.1.3 组件编写最佳实践

1. **Props（属性）声明**
    使用 `<script>` 中的 `export let` 定义接口：

    ```svelte
    <!-- src/lib/components/Button.svelte -->
    <script>
      export let variant = 'primary'; // 默认值
      export let size = 'md';
      export let disabled = false;
    </script>

    <button
      class="btn btn--{variant} btn--{size}"
      disabled={disabled}
    >
      <slot /> <!-- 支持插槽内容 -->
    </button>

    <style>
      .btn { /* ... */ }
      .btn--primary { /* ... */ }
    </style>
    ```

2. **TypeScript 支持（推荐）**

    ```ts
    <!-- Button.svelte (启用 TS) -->
    <script lang="ts">
      export let variant: 'primary' | 'secondary' = 'primary';
      export let size: 'sm' | 'md' | 'lg' = 'md';
      export let disabled: boolean = false;
    </script>
    ```

    或通过 `$$Props` 声明（适用于复杂场景）：
    ```ts
    <script lang="ts">
      interface $$Props {
        variant?: 'primary' | 'secondary';
        size?: 'sm' | 'md' | 'lg';
        disabled?: boolean;
      }
    </script>
    ```

3. 在页面中使用组件

    ```svelte
    <!-- src/routes/+page.svelte -->
    <script>
      import Button from '$lib/components/Button.svelte';
      import Card from '$lib/components/Card.svelte';
    </script>

    <Card title="Welcome">
      <p>This is a reusable card.</p>
      <Button variant="primary" on:click={() => alert('Clicked!')}>
        Click me
      </Button>
    </Card>
    ```


### 3.1.4 高级技巧


1. **组件分组与 barrel 文件**

    如果组件很多，可用 `index.js` 聚合导出：

    ```js
    // src/lib/components/index.js
    export { default as Button } from './Button.svelte';
    export { default as Card } from './Card.svelte';
    export { default as Header } from './Header/Header.svelte';
    ```

    使用时：
    ```svelte
    <script>
      import { Button, Card } from '$lib/components';
    </script>
    ```

    > 注意：这会**增加 bundle 体积**（无法 tree-shake 未使用的组件），除非你用支持  tree-shaking 的构建工具（Vite 默认支持 ES modules tree-shaking，但需确保导出是独立的）。

    **更安全的做法**：保持直接路径导入。


2. **服务端 vs 客户端组件**

    - 所有 `src/lib/components/` 中的组件**默认同时用于 SSR 和 CSR**
    - 如果组件**只能在客户端运行**（如使用 `window`），需：

      ```svelte
      <!-- ClientOnly.svelte -->
      <script>
        import { browser } from '$app/environment';
        let mounted = false;

        if (browser) {
          mounted = true;
        }
      </script>
    
      {#if mounted}
        <!-- 你的 DOM 操作 -->
      {/if}
      ```

## 3.2 服务端配置

在 **SvelteKit** 项目中，`src/lib/server/` 是一个**社区广泛采用的约定目录**，用于存放**仅在服务端运行的逻辑**（如数据库操作、认证工具、API 客户端、敏感配置等）。虽然 SvelteKit 不强制要求此路径，但它能显著提升代码组织性、安全性和可维护性。

核心目的：**将服务端专用代码与客户端/共享代码隔离，避免意外泄露敏感逻辑或密钥到前端。**


### 3.2.1 典型目录结构

```
src/
├── lib/
│   ├── server/               ← 服务端专用逻辑
│   │   ├── db.ts             // 数据库连接
│   │   ├── auth.ts           // 认证工具（JWT、session）
│   │   ├── api/              // 内部 API 客户端
│   │   │   └── github.ts
│   │   └── utils.ts          // 服务端工具函数
│   ├── components/           // UI 组件（客户端+服务端均可）
│   └── utils.ts              // 共享工具（纯函数，无环境依赖）
├── routes/
│   └── profile/
│       └── +page.server.ts   // 可安全导入 $lib/server/*
└── hooks.server.ts           
```

> **关键规则**：  
> - `src/lib/server/` 中的代码 **只能在服务端文件中导入**（如 `+page.server.ts`, `hooks.server.ts`, `+server.ts`）  
> - **绝不能**在 `+page.svelte`、`+layout.svelte` 或 `hooks.client.js` 中导入！



### 3.2.2 为什么需要隔离？安全示例

- 危险做法：把数据库逻辑放错地方

    ```ts
    // src/lib/db.ts （错误！放在共享目录）
    export const db = new Database(process.env.DB_URL); // 包含密钥！
    ```

    如果在组件中不小心导入：
    ```svelte
    <!-- +page.svelte -->
    <script>
        import { db } from '$lib/db'; //  密钥会打包到前端 JS！
    </script>
    ```

- 正确做法：用 `src/lib/server/`

    ```ts
    // src/lib/server/db.ts
    import { DATABASE_URL } from '$env/static/private'; // 安全

    export const db = new Database(DATABASE_URL);
    ```

    只在服务端使用：
    ```ts
    // routes/profile/+page.server.ts
    import { db } from '$lib/server/db'; // 安全，不会出现在前端 bundle

    export const load = async ({ locals }) => {
      const user = await db.getUser(locals.userId);
      return { user };
    };
    ```

    > SvelteKit 构建时会**自动排除 `$lib/server` 代码**，确保它**永远不会出现在客户端 bundle 中**。

### 3.2.3 常见使用场景

1. **数据库连接**

    ```ts
    // src/lib/server/db.ts
    import { env } from '$env/dynamic/private';
    import postgres from 'postgres';

    const sql = postgres(env.DATABASE_URL);
    export default sql;
    ```

2. **认证逻辑**

    ```ts
    // src/lib/server/auth.ts
    import { cookies } from '@sveltejs/kit';
    import { jwtVerify } from 'jose';

    export async function validateSession(token: string) {
      try {
        const { payload } = await jwtVerify(token, secretKey);
        return payload.sub;
      } catch {
        return null;
      }
    }

    export function setSession(userId: string) {
      const token = signJWT(userId);
      cookies.set('session', token, { httpOnly: true, secure: true });
    }
    ```

3. **内部 API 封装**

    ```ts
    // src/lib/server/api/github.ts
    import { GITHUB_TOKEN } from '$env/static/private';

    export async function fetchGitHubUser(username: string) {
      const res = await fetch(`https://api.github.com/users/${username}`, {
        headers: { Authorization: `token ${GITHUB_TOKEN}` }
      });
      return res.json();
    }
    ```

4. **服务端工具函数**

    ```ts
    // src/lib/server/utils.ts
    export function sanitizeHtml(html: string) {
      // 使用 DOMPurify（仅服务端可用）
      return DOMPurify.sanitize(html);
    }

    export function rateLimit(ip: string) {
      // 检查 Redis 是否超限
    }
    ```

## 3.3 其他类型

### 3.3.1 `stores/` —— 全局状态管理

1. 作用

    存放 **Svelte 响应式 store**，用于跨组件/跨路由共享状态。

2. 文件命名约定

    - 使用 `.store.ts` 后缀（非强制，但清晰表明用途）
    - 示例：
        - `user.store.ts`：当前用户信息、登录状态
        - `cart.store.ts`：购物车商品列表
        - `theme.store.ts`：亮/暗主题切换

3. 正确用法示例

    ```ts
    // src/lib/stores/user.store.ts
    import { writable } from 'svelte/store';

    export const user = writable<{ id: string; name: string } | null>(null);
    ```

    ```svelte
    <!-- 在任何 .svelte 组件中 -->
    <script>
      import { user } from '$lib/stores/user.store';
    </script>

    {#if $user}
      <p>Hello, {$user.name}!</p>
    {/if}
    ```

4. 注意事项

    - **不要存储敏感数据**（如 token、密码）——这些应由服务端 session 管理
    - **SSR 安全**：初始值必须是静态的（不能依赖 `localStorage` 等浏览器 API）
    - **持久化**：如需保存到 `localStorage`，使用 `svelte-persisted-store` 或封装安全逻辑

### 3.3.2 `utils/` —— 工具函数库

1. 作用

    存放**纯函数工具**，无副作用、无环境依赖，**客户端和服务端均可安全使用**。

2. 常见文件

    | 文件 | 用途 |
    |------|------|
    | `helpers.ts` | 通用辅助函数（如 `slugify`, `deepEqual`） |
    | `formatters.ts` | 数据格式化（如 `formatDate`, `currency`） |
    | `validators.ts` | 表单校验逻辑（如 `isValidEmail`） |

3. 正确用法示例

    ```ts
    // src/lib/utils/formatters.ts
    export const formatDate = (date: Date): string =>
      date.toLocaleDateString('en-US', {
        year: 'numeric',
        month: 'short',
        day: 'numeric'
      });
    ```

    ```svelte
    <!-- 在组件或 +page.server.ts 中均可使用 -->
    <script>
      import { formatDate } from '$lib/utils/formatters';
    
      const now = new Date();
    </script>

    <p>Published: {formatDate(now)}</p>
    ```

4. 注意事项

    - **必须是纯函数**（相同输入 → 相同输出）
    - **不能依赖浏览器 API**（如 `window`, `document`）——否则 SSR 会崩溃
    - 如需环境相关逻辑，拆分到 `src/lib/client/` 或 `src/lib/server/`


### 3.3.3 `styles/` —— 全局样式资源

1. 作用

    集中管理**全局 CSS**，避免重复定义。

2. 常见文件

    | 文件 | 用途 |
    |------|------|
    | `global.css` | 全局重置样式、body 样式、通用类 |
    | `variables.css` | CSS 自定义属性（主题色、间距、断点等） |

3. 正确用法示例

    ```css
    /* src/lib/styles/variables.css */
    :root {
      --color-primary: #3b82f6;
      --space-md: 1rem;
      --radius: 6px;
    }

    .dark {
      --color-bg: #111;
      --color-text: #fff;
    }
    ```

    ```css
    /* src/lib/styles/global.css */
    @import './variables.css';

    body {
      margin: 0;
      font-family: system-ui;
      background-color: var(--color-bg);
      color: var(--color-text);
    }

    .btn {
      padding: var(--space-md);
      border-radius: var(--radius);
    }
    ```

4. 在 SvelteKit 中引入全局样式
    在 `src/app.html` 或 `+layout.svelte` 中引入：

    ```svelte
    <!-- src/routes/+layout.svelte -->
    <script>
      // 引入一次即可，全局生效
      import '$lib/styles/global.css';
    </script>

    <slot />
    ```

    > **优势**：  
    > - 所有组件自动继承变量  
    > - 主题切换只需切换 class（如 `<html class="dark">`）

5. 注意事项

    - **不要放组件局部样式**——组件样式应写在 `<style>` 标签内（Svelte 默认 scoped）
    - **避免过度使用 `:global()`**——破坏组件封装性
