# 四、其他相关

## 4.1 渲染模式 

### 4.1.1 渲染类型

SvelteKit 是一个全栈元框架，原生支持三种核心渲染模式：

- SSR（Server-Side Rendering）：服务端渲染，动态内容 + SEO 友好
- SSG（Static Site Generation）：静态生成，构建时预渲染 HTML
- CSR（Client-Side Rendering）：纯客户端渲染（默认后备行为）

| 模式 | 何时渲染 | 适用场景 | SEO | 性能 |
|------|--------|--------|-----|------|
| SSR | 每次请求时（服务端） | 动态内容（用户仪表盘、实时数据） | 优秀 | 快（首屏） |
| SSG | 构建时（一次生成） | 静态内容（博客、文档、营销页） | 优秀 | 极快（CDN） |
| CSR | 浏览器加载后 | 内部工具、管理后台（无需 SEO） | 差 | 首屏慢 |

SvelteKit 默认采用 混合渲染：

- 首屏：SSR（或 SSG）
- 后续导航：CSR（SPA 体验）

### 4.1.2 全局配置（`svelte.config.js`）

通过 **适配器（Adapter）** 决定部署目标和默认渲染行为：

```js
// svelte.config.js
import adapter from '@sveltejs/adapter-auto'; // 自动选择适配器
// 或指定：
// import adapter from '@sveltejs/adapter-node';    // SSR（Node 服务器）
// import adapter from '@sveltejs/adapter-static';  // SSG（静态站点）

/** @type {import('@sveltejs/kit').Config} */
const config = {
    kit: {
    adapter: adapter(),
        // 全局 prerender 设置
        prerender: {
            entries: ['/', '/about', '/blog'] // 显式指定 SSG 路由
        }
    }
};

export default config;
```

> 🔔 **关键**：
> 
> *   `adapter-static` → 强制 SSG（所有页面必须可静态生成）
> *   `adapter-node` / `adapter-cloudflare` 等 → 支持 SSR + SSG 混合


### 4.1.3 按路由配置渲染模式

SvelteKit 允许**每个路由单独控制**是否 SSR、SSG 或 CSR。

1. **启用 SSG（静态生成）**

    在 `+page.js` 或 `+layout.js` 中设置：

    ```js
    // src/routes/blog/+page.js
    export const prerender = true; // ✅ 构建时生成静态 HTML
    ```

    > 要求：
    > 
    > *   `load` 函数不能依赖请求时信息（如 `cookies`, `request.headers`）
    > *   所有数据必须在构建时可获取

2. **禁用 SSR（强制 CSR）**

    ```js
    // src/routes/dashboard/+page.js
    export const ssr = false; // ❌ 不在服务端渲染，仅客户端激活
    export const csr = true;  // （默认 true，可省略）
    ```

    > 适用场景：
    > 
    > *   内部管理面板（无需 SEO）
    > *   重度交互应用（如画板、游戏）


3. **混合模式（默认）**

    ```js
    // src/routes/+page.js
    // 不设置 ssr/prerender → 默认行为：
    // - 首屏：SSR（服务端渲染 HTML）
    // - 客户端：水合（hydration）后变为 CSR
    ```

### 4.1.4 数据加载与渲染模式的关系

1. SSR / SSG：使用 `+page.server.js`

    ```js
    // src/routes/profile/+page.server.js
    export async function load({ locals, params }) {
      // 可安全访问数据库、私有 API
      const user = await db.getUser(params.id);
      return { user };
    }
    ```

2. CSR：只能使用 `+page.js`（无服务端上下文）

    ```js
    // src/routes/app/+page.js
    export async function load() {
      // 仅能调用公开 API
      const data = await fetch('/api/public-data').then(r => r.json());
      return { data };
    }
    ```

    > 如果设置 `ssr: false`，则 **`+page.server.js` 不会运行**！

## 4.2 生命周期钩子

在 SvelteKit 中，`hooks.client.js` 和 `hooks.server.js` 是两个核心的**生命周期钩子文件**，用于在请求/导航的不同阶段插入自定义逻辑。它们分别运行在**客户端**和**服务端**，职责完全不同。

### 4.2.1 总体对比

| 特性  | `hooks.server.js` | `hooks.client.js` |
| --- | --- | --- |
| **运行环境** | 服务端（Node.js / Edge Runtime） | 客户端（浏览器） |
| **触发时机** | 每个 HTTP 请求（包括页面加载、API 调用、actions） | 每次客户端导航（SPA 跳转） |
| **可访问内容** | `request`, `cookies`, `env`, `platform`, `locals` | `navigation`, `route`, `url` |
| **主要用途** | 认证、日志、权限控制、数据预处理 | 页面切换动画、埋点、滚动恢复、错误上报 |
| **是否影响 SEO** | 是（参与 SSR） | 否（仅客户端） |

> **一句话总结**：
> 
> *   **`server hooks` = 后端中间件**
> *   **`client hooks` = 前端导航拦截器**



### 4.2.2 `hooks.server.js` —— 服务端钩子

1. 执行流程

    ```text
    请求进入 → handleFetch (可选) → handle (主逻辑) → 返回响应
    ```

2. 核心函数

    1. `handle`（最常用）

    在**每个服务端请求前**执行（包括 `load`、`actions`、`+server.js`）。

    ```js
    // src/hooks.server.js
    import { sequence } from '@sveltejs/kit/hooks';

    /** @type {import('@sveltejs/kit').Handle} */
    async function auth({ event, resolve }) {
      const session = event.cookies.get('session');
    
      // 将用户信息注入 locals（所有服务端函数可访问）
      if (session) {
        event.locals.user = await db.getUserBySession(session);
      } else {
        event.locals.user = null;
      }

      // 继续处理请求
      return resolve(event);
    }

    /** @type {import('@sveltejs/kit').Handle} */
    async function logger({ event, resolve }) {
      const start = Date.now();
      const response = await resolve(event);
      const duration = Date.now() - start;
      console.log(`${event.request.method} ${event.url.pathname} - ${duration}ms`);
      return response;
    }

    // 使用 sequence 组合多个钩子（按顺序执行）
    export const handle = sequence(auth, logger);
    ```

    > **典型用例**：
    > 
    > *   用户认证（设置 `locals.user`）
    > *   权限检查（如 `/admin` 路由拦截）
    > *   请求日志
    > *   多语言 i18n 初始化
    > *   API 代理（修改 `fetch` 行为）


    2. `handleFetch`（高级用法）

    拦截组件中 `load()` 函数使用的 `fetch` 调用。

    ```js
    // src/hooks.server.js
    export async function handleFetch({ request, fetch }) {
      // 例如：为内部 API 自动添加认证头
      if (request.url.startsWith('https://api.myapp.com')) {
        request.headers.set('Authorization', `Bearer ${process.env.INTERNAL_TOKEN}`);
      }
      return fetch(request);
    }
    ```

    > 注意：仅影响 **服务端 `load` 中的 `fetch`**，不影响客户端 `fetch`。


### 4.2.3 `hooks.client.js` —— 客户端钩子

1. 执行流程

    ```txt
    用户点击链接/调用 goto() → handleError (可选) → handle (主逻辑) → 页面切换
    ```

2. 核心函数

    1. `handle`（最常用）
    
    在**每次客户端导航前**执行（仅 SPA 跳转，不包括首次页面加载）。
    
    ```js
    // src/hooks.client.js
    /** @type {import('@sveltejs/kit').HandleClient} */
    export async function handle({ event, resolve }) {
      // 例如：页面切换时显示加载条
      document.querySelector('#loading-bar')?.classList.add('active');
    
      const response = await resolve(event);
    
      // 导航完成后隐藏加载条
      document.querySelector('#loading-bar')?.classList.remove('active');
    
      return response;
    }
    ```
    
    > **典型用例**：
    > 
    > *   全局加载指示器
    > *   页面切换动画
    > *   埋点统计（记录用户行为）
    > *   滚动位置保存/恢复
    > *   在线状态检测


    2. `handleError`（错误处理）

    捕获**客户端运行时错误**（如组件渲染错误、`load` 抛出异常）。

    ```js
    // src/hooks.client.js
    /** @type {import('@sveltejs/kit').HandleClientError} */
    export function handleError({ error, event }) {
      // 上报错误到 Sentry 等监控服务
      console.error('Client error:', error);
      Sentry.captureException(error, { extra: { url: event.url.href } });
    
      // 可返回自定义错误信息（但不会改变 UI）
      return {
        message: 'An unexpected error occurred'
      };
    }
    ```

    > 注意：
    > 
    > *   不会阻止错误发生，仅用于**日志记录**
    > *   实际错误界面由 `+error.svelte` 控制



## 4.3 动态路由参数验证

在 SvelteKit 中，**`/src/params`** 是一个**可选的特殊目录**，用于**自定义动态路由参数（`[param]`）的解析和验证逻辑**。

它的核心作用是：

> **当你在路由中使用 `[id]`、`[slug]` 等动态参数时，可以通过 `src/params/xxx.js` 定义该参数的校验规则和类型转换逻辑。**


### 4.3.1 为什么需要 `src/params`？

默认情况下，SvelteKit 会把 URL 中的动态参数（如 `/blog/[slug]`）作为 **字符串** 传递给你的页面：

```svelte
<!-- 访问 /blog/hello-world -->
<script>
  export let data;
  // data.slug === "hello-world" （字符串）
</script>
```

但很多时候你需要：

*   验证参数格式（如 `id` 必须是数字）
*   自动转换类型（如字符串 `"123"` → 数字 `123`）
*   拒绝不合法参数（返回 404）

这时候 `src/params` 就派上用场了！


### 4.3.2 基本用法

- 步骤 1：创建参数解析器文件

    文件名必须与路由中的参数名一致：


    ```plain
    src/
    ├── params/
    │   ├── id.js        // 处理 [id]
    │   ├── slug.js      // 处理 [slug]
    │   └── date.js      // 处理 [date]
    └── routes/
        └── blog/
            └── [slug]/+page.svelte
    ```

- 步骤 2：导出 `match` 和/或 `parse` 函数

    ```js
    // src/params/id.js

    /**
     * 校验参数是否合法（正则或函数）
     * @param {string} param - URL 中的原始字符串
     * @returns {boolean}
     */
    export function match(param) {
      return /^\d+$/.test(param); // 只允许纯数字
    }

    /**
     * 将字符串转换为目标类型（可选）
     * @param {string} param
     * @returns {number}
     */
    export function parse(param) {
      return parseInt(param, 10);
    }
    ```

    > 如果只导出 `match`，参数仍为字符串；  
    > 如果同时导出 `parse`，参数会被自动转换。


### 4.3.3 完整示例

- 示例 1：数字 ID 参数

    ```js
    // src/params/id.js
    export const match = (param) => /^\d+$/.test(param);
    export const parse = (param) => Number(param);
    ```

    路由：

    ```svelte
    <!-- src/routes/users/[id]/+page.svelte -->
    <script>
      /** @type {import('./$types').PageData} */
      export let data;
      // data.id 是 number 类型！
    </script>

    <h1>User ID: {data.id}</h1>
    ```

    服务端加载：

    ```js
    // src/routes/users/[id]/+page.server.js
    import type { PageServerLoad } from './$types';

    export const load = (async ({ params }) => {
      // ✅ params.id 已经是 number！
      const user = await db.getUserById(params.id);
      return { user };
    }) satisfies PageServerLoad;
    ```

    > 如果访问 `/users/abc`，SvelteKit 会自动返回 **404 Not Found**（因为 `match` 返回  false）。


- 示例 2：日期参数（YYYY-MM-DD）

    ```js
    // src/params/date.js
    const DATE_REGEX = /^\d{4}-\d{2}-\d{2}$/;

    export function match(param) {
      if (!DATE_REGEX.test(param)) return false;
      const date = new Date(param);
      return !isNaN(date.getTime()); // 验证是否为有效日期
    }

    export function parse(param) {
      return new Date(param); // 转为 Date 对象
    }
    ```

    使用：

    ```js
    // routes/events/[date]/+page.server.js
    export const load = ({ params }) => {
      // params.date 是 Date 对象！
      const events = await getEventsOnDate(params.date);
      return { events };
    };
    ```

- 示例 3：仅校验，不转换（保留字符串）

    ```js
    // src/params/slug.js
    // 只允许小写字母、数字、连字符
    export const match = (param) => /^[a-z0-9-]+$/.test(param);

    // 不导出 parse → 保持字符串
    ```
