# 四、其他功能

## 4.1 服务端基础

- `server/api/`：定义 RESTful API 接口（自动挂载到 `/api/` 路径）
- `server/routes/`：定义自定义服务端路由（如 `/sitemap.xml`、`/health`）
- `server/middleware/`：定义服务端中间件（请求预处理、日志、CORS 等）

```bash
server/
├── api/                  # 业务 API
│   ├── auth/
│   ├── users/
│   └── products/
├── routes/               # 非 API 路由
│   ├── sitemap.xml.get.ts
│   └── health.get.ts
├── middleware/           # 服务端中间件
│   ├── 01.cors.ts
│   ├── 02.logger.ts
│   └── 03.auth.ts
└── utils/                # 服务端工具
    ├── db.ts            # 数据库连接
    └── mailer.ts        # 邮件服务
```

关键工具函数（服务端专用）

| 函数 | 用途 |
|------|------|
| `readBody(event)` | 读取并解析请求体（JSON/form-data） |
| `getQuery(event)` | 获取 URL 查询参数 |
| `getRouterParam(event, 'id')` | 获取动态路由参数 |
| `getCookie(event, 'name')` | 读取 Cookie |
| `setCookie(event, 'name', 'value', options)` | 设置 Cookie |
| `setHeader(event, key, value)` | 设置响应头 |
| `setResponseStatus(event, 404)` | 设置状态码 |
| `createError({ statusCode, statusMessage })` | 抛出标准错误 |
| `sendRedirect(event, '/path')` | 服务端重定向 |


### 4.1.1 一、`server/api/` —— 自动注册的 API 路由

1. 特点

    - 所有文件自动注册为 **`/api/**`** 的 API 端点
    - 支持 HTTP 方法（`.get.ts`, `.post.ts`）或通用处理
    - 自动序列化响应（返回对象 → JSON）
    - SSR 安全（可访问私有配置、数据库等）

2. 目录结构

    ```bash
    server/
    └── api/
        ├── hello.get.ts          # GET /api/hello
        ├── user.post.ts          # POST /api/user
        ├── products/[id].ts      # 动态路由：GET/POST /api/products/123
        └── auth/
            ├── login.post.ts     # POST /api/auth/login
            └── logout.post.ts    # POST /api/auth/logout
    ```

3. 示例 1：简单 GET

    ```ts
    // server/api/hello.get.ts
    export default defineEventHandler(() => {
      return { message: 'Hello from Nuxt Server!' };
    });
    ```

    > 访问 `http://localhost:3000/api/hello` → 返回 JSON


4. 示例 2：带验证的 POST（用户注册）
    ```ts
    // server/api/auth/register.post.ts
    import { z } from 'zod';

    const registerSchema = z.object({
      email: z.string().email(),
      password: z.string().min(8)
    });

    export default defineEventHandler(async (event) => {
      const body = await readBody(event);
      const { email, password } = registerSchema.parse(body);

      // 模拟数据库操作（实际应调用 DB）
      const user = { id: Date.now(), email };

      // 设置 Cookie（安全：httpOnly + secure）
      setCookie(event, 'auth_token', 'fake-jwt-token', {
        httpOnly: true,
        secure: process.env.NODE_ENV === 'production',
        maxAge: 60 * 60 * 24 * 7, // 7 天
        path: '/'
      });

      return { success: true, user };
    });
    ```

    > 💡 使用 `setCookie(event, ...)` 而非 `useCookie`（后者是客户端 composable）

3. 示例 3：动态路由 + 数据库查询

    ```ts
    // server/api/products/[id].ts
    export default defineEventHandler(async (event) => {
      const id = getRouterParam(event, 'id'); // 获取 :id 参数

      if (!/^\d+$/.test(id)) {
        throw createError({ statusCode: 400, statusMessage: 'Invalid ID' });
      }

      // 模拟 DB 查询
      const product = await db.product.findUnique({ where: { id: Number(id) } });

      if (!product) {
        throw createError({ statusCode: 404, statusMessage: 'Product not found' });
      }

      return product;
    });
    ```

### 4.1.2 `server/routes/` —— 自定义服务端路由

1. 用途
    - 非 `/api/` 前缀的路由（如 SEO 文件、Webhook、静态内容生成）
    - 返回非 JSON 内容（XML、纯文本、重定向等）

2.  目录结构

    ```bash
    server/
    └── routes/
        ├── sitemap.xml.get.ts    # GET /sitemap.xml
        ├── robots.txt.get.ts     # GET /robots.txt
        ├── webhook.post.ts       # POST /webhook
        └── health.get.ts         # GET /health
    ```

3. 示例 1：生成 sitemap.xml

    ```ts
    // server/routes/sitemap.xml.get.ts
    export default defineEventHandler(() => {
      const sitemap = `<?xml version="1.0" encoding="UTF-8"?>
    <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
      <url><loc>https://example.com/</loc></url>
      <url><loc>https://example.com/about</loc></url>
    </urlset>`;

      setHeader(event, 'Content-Type', 'application/xml');
      return sitemap;
    });
    ```


4.  示例 2：健康检查

    ```ts
    // server/routes/health.get.ts
    export default defineEventHandler(() => {
      return { status: 'ok', timestamp: new Date().toISOString() };
    });
    ```

    > 可用于 Docker/K8s 健康探针



### 4.1.3 `server/middleware/` —— 服务端中间件

1. 特点

    - **仅在服务端运行**
    - 按 **文件名 ASCII 顺序** 执行（建议前缀数字：`01.auth.ts`）
    - 可修改请求/响应、终止流程、记录日志等

2. 目录结构

    ```bash
    server/
    └── middleware/
        ├── 01.cors.ts            # CORS 头
        ├── 02.logger.ts          # 请求日志
        ├── 03.auth.ts            # API 认证
        └── 99.error-handler.ts   # 全局错误处理
    ```

3. 示例 1：CORS 中间件

    ```ts
    // server/middleware/01.cors.ts
    export default defineEventHandler((event) => {
      const allowedOrigins = ['https://yourdomain.com'];
      const origin = getHeader(event, 'origin');

      if (origin && allowedOrigins.includes(origin)) {
        setHeader(event, 'Access-Control-Allow-Origin', origin);
      }
      setHeader(event, 'Access-Control-Allow-Credentials', 'true');
      setHeader(event, 'Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS');
      setHeader(event, 'Access-Control-Allow-Headers', 'Content-Type, Authorization');

      // 处理预检请求
      if (event.node.req.method === 'OPTIONS') {
        setResponseStatus(event, 204);
        return '';
      }
    });
    ```


3. 示例 2：API 认证中间件

    ```ts
    // server/middleware/03.auth.ts
    export default defineEventHandler((event) => {
      // 跳过公开路由
      if (event.path.startsWith('/api/auth')) return;

      const token = getCookie(event, 'auth_token');
      if (!token || token !== 'fake-jwt-token') {
        throw createError({ statusCode: 401, statusMessage: 'Unauthorized' });
      }
    });
    ```

    > 使用 `getCookie(event, name)` 读取 Cookie（服务端安全）



4. 示例 3：全局错误处理
    ```ts
    // server/middleware/99.error-handler.ts
    export default defineEventHandler((event, { skip }) => {
      // 注意：错误中间件需放在最后，且通常通过 Nitro 配置更合适
      // 实际推荐使用 nitro.hooks（见下文）
    });
    ```

    >  更推荐在 `nuxt.config.ts` 中配置全局错误处理：
    > ```ts
    > export default defineNuxtConfig({
    >   nitro: {
    >     hooks: {
    >       'render:error': (error, { event }) => {
    >         console.error('Server error:', error);
    >       }
    >     }
    >   }
    > });
    > ```


## 4.2 连接数据库

1. 安装插件

    ```sh
    pnpm install mysql2
    ```
2. 测试连接

    ```ts
    import msyql from 'mysql2';

    // 创建一个数据库连接
    const connection = msyql.createConnection({
        host: 'localhost',
        user:  'root',
        password: '123456',
        database: 'jbook'
    });
    // 连接连接池
    const pool = msyql.createPool({
        host: 'localhost',
        user:  'root',
        password: '123456',
        database: 'jbook',
        waitForConnections: true,
        connectionLimit: 10,
        queueLimit: 0
    })  


    // 测试连接数据库
    connection.connect((err)=>{
        console.log("数据库连接成功");
    })  

    // 测试连接池
    pool.getConnection((err, conn)=>{
        console.log("数据库连接池成功");
    });
    ```
3. 使用连接池应用

    ```ts
    // utils/db.ts
    import msyql from 'mysql2';

    export const getDB = () =>{
        // 连接连接池
        const pool = msyql.createPool({
            host: 'localhost',
            user:  'root',
            password: '123456',
            database: 'jbook',
            waitForConnections: true,
            connectionLimit: 10,
            queueLimit: 0
        });

        // 类型断言
        return pool.promise() as any;

    }
    ```

    ```ts
    // api/user.get.ts
    import { getDB } from '../utils/db';

    export default defineEventHandler(async (event)=>{

        const [rows,fields] = await getDB().query('SELECT * FROM users LIMIT 10');
        console.log('users:', rows);

    });
    ```
## 4.3 页面渲染模式

1. SSR、CSR、SSG 三者的对比

    | 维度 | SSR | CSR | SSG |
    |------|-------------------------------|-------------------------------|-------------------------------|
    | 渲染时机 | 用户请求时，服务端实时渲染 HTML | 浏览器下载 JS 后，客户端动态渲染 | 构建时（build time）预渲染 为静态 HTML |
    | 首屏速度 | 快（直接返回完整 HTML） | 慢（需下载 + 执行 JS） |  极快（纯静态文件，CDN 直达） |
    | SEO 友好性 | 优秀（搜索引擎可抓取完整 HTML） | 差（初始 HTML 为空） | 最佳（纯静态，无 JS 依赖） |
    | 数据动态性 | 支持实时数据（如用户信息、库存） | 支持（通过 API 获取） |  仅限构建时已知数据（内容更新需重新构建） |
    | 服务器压力 |  高（每次请求都需渲染） |  低（只提供静态资源） | 极低（无需运行时服务端） |
    | 部署复杂度 | 中（需 Node.js/Serverless 环境） | 低（任意静态托管） | 低（任意静态托管） |
    | 典型框架 | Nuxt, Next.js, Remix | Vue CLI SPA, React CRA | Nuxt (generate), Next.js (export), Astro, Hugo |

2. **SSR（服务端渲染）—— 默认模式**

    *   **工作方式**：
        *   用户请求 URL → Nuxt 服务端执行 `+page.vue` + `+page.server.ts`
        *   生成完整 HTML → 返回给浏览器
        *   浏览器激活（Hydration）→ 变成交互式 SPA
    *   **优点**：
        *   SEO 友好
        *   首屏加载快
        *   支持动态数据（如用户个性化内容）
    *   **启用方式**：
        ```ts
        // nuxt.config.ts（默认就是 SSR）
        export default defineNuxtConfig({
            ssr: true // 默认值
        });
        ```
        
    *   **典型场景**：电商首页、新闻站、用户中心


2. **CSR（客户端渲染）—— 关闭 SSR**

    *   **工作方式**：
        *   服务端只返回空 HTML + JS bundle
        *   所有渲染逻辑在浏览器中执行
    *   **启用方式**：

        ```ts
        // pages/dashboard.vue
        <script setup>
        definePageMeta({
            ssr: false // 仅该页面禁用 SSR
        });
        </script>
        ```

        或全局关闭：

        ```ts
        // nuxt.config.ts
        export default defineNuxtConfig({
            ssr: false // 整个应用变成 SPA
        });
        ```

    *   **优点**：
        *   简化部署（可托管在 CDN）
        *   适合内部工具、管理后台
    *   **缺点**：
        *   SEO 差
        *   首屏白屏时间长

3. **SSG（静态站点生成）—— 构建时生成 HTML**

    *   **工作方式**：
        *   `nuxt generate` 命令在构建时爬取所有路由
        *   为每个路由生成静态 `.html` 文件
        *   部署后直接由 CDN 提供服务
    *   **启用方式**：

        ```ts
        // nuxt.config.ts
        export default defineNuxtConfig({
          ssr: true,
          nitro: {
            static: true // 启用 SSG
          }
        });
        ```

        然后运行：

        ```bash
        npm run generate  # 生成 .output/public/ 下的静态文件
        ```

    *   **动态路由需指定路径**：

        ```ts
        // routes/blog/[slug].vue
        export const prerender = true;

        // 或在 nuxt.config.ts 中配置
        nitro: {
          prerender: {
            routes: ['/blog/post-1', '/blog/post-2']
          }
        }
        ```

    *   **典型场景**：博客、文档站、营销落地页


## 4.4 页面配置相关

### 4.4.1 填写title与meta

在 nuxt.config.ts 添加这些信息

```js
app: {
  head: {
    title: 'NUXT4仿简书',
    meta: [
      { charset: 'utf-8' },
      { name: 'viewport', content: 'width=device-width, initial-scale=1' },
      { name: 'description', content: '只是仿照简书的一个项目，没有任何商业用途，只是为了学习NUXT4。' },
      { name: 'keywords', content: 'NUXT4,仿简书,学习项目' }
    ],
  }
},
```

### 4.4.2 运行时环境变量

1. 设置变量 nuxt.config.ts

    ```ts
    runtimeConfig:{
        // 私密
        SecretId: process.env.SECRET_ID, 
        SecretKey: process.env.SECRET_KEY, 
        public:{
            // 公开 
            Bucket: process.env.BUCKET,
            Region: process.env.REGION,
        }
    },
    ```
2. 使用变量

    ```js
    const conf = useRuntimeConfig()

    // 配置参数
    var config = {
        secretId: conf.SecretId, // 固定密钥
        secretKey: conf.SecretKey, // 固定密钥
        //...
    }
    ```

### 4.4.3 启动与构建使用不通变量

里面--dotenv 使用不通的环境变量，由于nuxt4不会读取系统的环境变量，只能这样写，或者都用.env

```json
"scripts": {
    "build": "nuxt build --dotenv .env.production",
    "dev": "nuxt dev --dotenv .env.local",
}
```

### 4.4.4 baseURL

1. 服务端请求

    - 本地启动地址设置环境变量

        ```js
         hooks: {
            listen(server, { host, port }) {
                const protocol = 'http'
                const hostname = host === '0.0.0.0' ? 'localhost' : host
                const url = `${protocol}://${hostname}:${port}`
                process.env.NUXT_URL = url
            }
        },
        ```
    - 使用

        ```js
        baseURL: config.NUXT_URL,
        ```
2. 客户端请求

    ```js
    baseURL: window.location.origin,
    ```
