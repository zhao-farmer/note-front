# 一、读取信息

## 1.1 Input读取元信息

### 1.1.1 Input介绍

1. Input 类是什么？

    `Input` 是 mediabunny 的**核心入口类**，用于：

    - 打开媒体文件（视频/音频）
    - 读取容器格式、时长、元数据、轨道信息
    - 获取视频/音频轨道用于解码、生成缩略图
    - 管理资源释放

2. 构造函数
    ```javascript
    const input = new Input({
        source: MediaSource,  // 必须：BlobSource / UrlSource
        formats: Format[]    // 可选：支持的格式列表，默认 ALL_FORMATS
    });
    ```

3. 你代码里用到的 **所有方法官方文档**

    1. `await input.canRead()`
        **判断媒体是否能被解析读取**
        - 返回：`Promise<boolean>`
        - 用途：检查文件是否损坏、格式是否支持

    2. `await input.getFormat()`
        **获取媒体容器格式**
        - 返回：`Promise<Format>`
        - 包含：`name`（如 MP4、MKV、WAV、MP3）

    3. `await input.getMimeType()`
        **获取 MIME 类型**
        - 返回：`Promise<string>`
        - 例：`video/mp4`、`audio/wav`、`audio/mpeg`

    4. `await input.computeDuration()`
        **计算媒体总时长（秒）**
        - 返回：`Promise<number>`
        - 精度：微秒级

    5. `await input.getFirstTimestamp()`
        **获取媒体起始时间戳**
        - 返回：`Promise<number>`
        - 某些剪辑视频不是从 0 开始

    6. `await input.getMetadataTags()`
        **获取元数据标签**
        - 返回：`Promise<Record<string, string>>`
        - 包含：标题、作者、编码器、创建时间等

    7. `input.dispose()`
        **释放资源（必须调用！）**
        - 关闭文件、释放内存、销毁解码器

4. 官方说明总结
    - **`Input` 是媒体文件的顶层入口**
    - 负责**解析文件、读取信息、提供轨道**
    - 所有方法都是 **async/await**
    - 使用完必须 **dispose()** 释放内存
    - 支持：MP4/MKV/WebM/MP3/WAV/AAC/FLAC 等几乎所有格式

### 1.1.2 代码实例

1. 代码

    ```html
    <!DOCTYPE html>
    <html>
    <head>
      <meta charset="utf-8">
      <title>Mediabunny 读取视频文件元数据信息</title>
    </head>
    <body>
      <pre id="log"></pre>

      <script type="module">
        import { Input, ALL_FORMATS, BlobSource } from "../../js/mediabunny.1.42.mjs";
        const log = document.getElementById('log');

        // 你要读取的视频文件名列表
        const videoNames = ['video/01.mp4', 'video/02.mp4', 'audio/01.wav',"audio/02.mp3"];
        (async()=>{
          log.textContent = `开始读取 ${videoNames.length} 个视频文件...\n`;

          for (const name of videoNames) {
            const url = `../../${name}`;
            log.textContent += `\n=== 正在请求: ${url} ===\n`;

            try {
              // 用 fetch 获取文件流
              const res = await fetch(url);
              if (!res.ok) throw new Error(`请求失败: ${res.status}`);

              // 转成 Blob 再用 BlobSource 读取
              const blob = await res.blob();
              const input = new Input({
                formats: ALL_FORMATS,
                source: new BlobSource(blob)
              });

              const canRead = await input.canRead();
              const format = await input.getFormat();
              const mimeType = await input.getMimeType();
              const duration = await input.computeDuration();
              const firstTime = await input.getFirstTimestamp();
              const metadataTags = await input.getMetadataTags();

              log.textContent += [
                `可读取：${canRead}`,
                `格式：${format.name}`,
                `MIME：${mimeType}`,
                `总时长：${duration.toFixed(2)}s`,
                `起始时间：${firstTime}s`,
                `元数据：${JSON.stringify(metadataTags, null, 2)}`
              ].join('\n') + '\n';

              input.dispose();
            } catch (err) {
              log.textContent += `错误：${err.message}\n`;
            }
          }
        })();

      </script>
    </body>
    </html>
    ```

## 1.2 创建相关

### 1.2.1 输入格式

#### 1. 核心体系概览

1. 基类与子类

    这些是 `mediabunny` 中所有的**输入格式类**，每个对应一种媒体容器格式：

    | 类名 | 对应格式 | 常见后缀 | 说明 |
    |---|---|---|---|
    | `InputFormat` | 抽象基类 | - | 所有格式的父类，定义基础接口 |
    | `AdtsInputFormat` | AAC ADTS 流 | `.aac` | AAC 裸流 |
    | `FlacInputFormat` | FLAC 音频 | `.flac` | 无损音频 |
    | `IsobmffInputFormat` | ISO BMFF 容器 | `.mp4` `.mov` | MP4 / MOV 的父类 |
    | `HlsInputFormat` | HLS 直播流 | `.m3u8` | 流媒体协议 |
    | `MatroskaInputFormat` | Matroska 容器 | `.mkv` `.webm` | MKV / WebM 的父类 |
    | `Mp3InputFormat` | MP3 音频 | `.mp3` | 有损音频 |
    | `Mp4InputFormat` | MP4 视频 | `.mp4` | 继承自 `IsobmffInputFormat` |
    | `MpegTsInputFormat` | MPEG-TS 流 | `.ts` `.mts` | 传输流 |
    | `OggInputFormat` | Ogg 容器 | `.ogg` `.opus` | 开源音频/视频容器 |
    | `QuickTimeInputFormat` | QuickTime 视频 | `.mov` | 继承自 `IsobmffInputFormat` |
    | `WaveInputFormat` | WAV 音频 | `.wav` | PCM 音频 |
    | `WebMInputFormat` | WebM 视频 | `.webm` | 继承自 `MatroskaInputFormat` |


2. 预定义常量

    这些是已经实例化好的单例对象，直接用于 `new Input({ formats: [...] })` 配置和格式判断：

    | 常量名 | 对应类 | 说明 |
    |---|---|---|
    | `ADTS` | `AdtsInputFormat` | AAC ADTS 流 |
    | `FLAC` | `FlacInputFormat` | FLAC 音频 |
    | `HLS` | `HlsInputFormat` | HLS 直播流 |
    | `MATROSKA` | `MatroskaInputFormat` | MKV 容器 |
    | `MP3` | `Mp3InputFormat` | MP3 音频 |
    | `MP4` | `Mp4InputFormat` | MP4 视频 |
    | `MPEG_TS` | `MpegTsInputFormat` | MPEG-TS 流 |
    | `OGG` | `OggInputFormat` | Ogg 容器 |
    | `QTFF` | `QuickTimeInputFormat` | MOV 视频 |
    | `WAVE` | `WaveInputFormat` | WAV 音频 |
    | `WEBM` | `WebMInputFormat` | WebM 视频 |

    **快捷组合常量**

    | 常量名 | 内容 | 说明 |
    |---|---|---|
    | `ALL_FORMATS` | 所有格式实例的数组 | 支持所有媒体格式 |
    | `HLS_FORMATS` | `[HLS]` | 仅支持 HLS 流 |



3. 格式类的继承关系

    理解继承关系能帮你更灵活地处理格式判断：

    ```
    InputFormat
    ├── AdtsInputFormat
    ├── FlacInputFormat
    ├── HlsInputFormat
    ├── IsobmffInputFormat
    │   ├── Mp4InputFormat      ← MP4 常量
    │   └── QuickTimeInputFormat ← QTFF 常量
    ├── MatroskaInputFormat
    │   ├── MatroskaInputFormat  ← MATROSKA 常量
    │   └── WebMInputFormat      ← WEBM 常量
    ├── Mp3InputFormat           ← MP3 常量
    ├── MpegTsInputFormat        ← MPEG_TS 常量
    ├── OggInputFormat           ← OGG 常量
    ├── WaveInputFormat          ← WAVE 常量
    ```

#### 2. 核心用法

1. 创建 `Input` 时指定格式

    你可以通过 `formats` 配置，限制 `mediabunny` 只解析你需要的格式，提高性能和安全性：

    ```javascript
    // 方式1：使用 ALL_FORMATS（默认，支持所有格式）
    const inputAll = new Input({
      source: new UrlSource(VIDEO_URL),
      formats: ALL_FORMATS
    });

    // 方式2：手动指定支持的格式（只支持 MP4 + WebM + MP3）
    const inputCustom = new Input({
      source: new UrlSource(VIDEO_URL),
      formats: [MP4, WEBM, MP3]
    });
    ```

2. 判断媒体的实际格式

    有两种方式，推荐用 `===`：

    ```javascript
    const format = await input.getFormat();

    // 推荐：用 === 直接和常量对比（单例，最准确）
    if (format === MP4) {
      console.log('这是 MP4 文件');
    } else if (format === WEBM) {
      console.log('这是 WebM 文件');
    } else if (format === MP3) {
      console.log('这是 MP3 文件');
    }

    // 方式2：用 instanceof 判断大类
    if (format instanceof IsobmffInputFormat) {
      console.log('这是 MP4 或 MOV 文件');
    } else if (format instanceof MatroskaInputFormat) {
      console.log('这是 MKV 或 WebM 文件');
    }
    ```

#### 3. 注意点

1. 你可能会用到的 `InputFormat` 实例属性
    从 `await input.getFormat()` 获取的 `format` 对象，包含这些关键属性：
    - `name`: 格式名称（如 `"MP4"`）
    - `mimeType`: 标准 MIME 类型（如 `"video/mp4"`）
    - `extensions`: 支持的文件扩展名数组（如 `[".mp4"]`）

    示例：
    ```javascript
    const format = await input.getFormat();
    console.log(format.name);       // "MP4"
    console.log(format.mimeType);   // "video/mp4"
    console.log(format.extensions); // [".mp4"]
    ```
2. 实用建议 

    1.  **优先使用预定义常量**：直接用 `MP4` / `WEBM` 这些单例对象，不要自己 new 格式类，避免多实例判断失败。
    2.  **按业务场景限制格式**：比如你的应用只处理视频，就用 `[MP4, WEBM, MATROSKA]` 代替 `ALL_FORMATS`，减少不必要的解析开销。
    3.  **用 `===` 做精确判断**：比 `instanceof` 更直接，也更符合 `mediabunny` 的设计。

### 1.2.2 加载资源

#### 1. 每个 Source 的介绍

1. `BufferSource`

    **核心用途**：从内存中的二进制数据读取媒体文件。
    - 支持：`ArrayBuffer`、`Uint8Array`
    - 典型场景：
        - 已经完全加载到内存中的媒体数据
        - 处理 fetch 下载的完整文件数据
    - 优点：
        - 读取速度最快，无 I/O 延迟
        - 无需额外网络/文件请求
    - 缺点：
        - 不支持范围请求（`slice()` 会一次性复制数据）
        - 大文件会占用大量内存
    - 示例：

        ```javascript
        const buffer = await (await fetch(url)).arrayBuffer();
        const source = new BufferSource(buffer);
        ```
2. `BlobSource`

    **核心用途**：从浏览器 `Blob` / `File` 对象读取（浏览器最常用）。
    - 支持：`Blob`、`File`（用户上传/拖放的文件）
    - 典型场景：
        - 用户上传的本地文件
        - 拖放的媒体文件
        - 从 canvas 生成的 Blob
    - 优点：
        - 支持范围请求，读取高效
        - 浏览器原生 API，兼容性好
    - 缺点：
        - 只能在浏览器环境使用
    - 示例：

        ```javascript
        const file = document.querySelector('input[type="file"]').files[0];
        const source = new BlobSource(file);
        ```
3. `UrlSource`

    **核心用途**：从 HTTP/HTTPS 网络地址读取媒体文件。
    - 支持：URL 字符串，支持 `http://`、`https://`
    - 典型场景：
        - 远程服务器上的媒体文件
        - CDN 上的视频/音频
    - 优点：
        - 原生支持 **HTTP 范围请求（206 Partial Content）**，可分段读取
        - 内置缓存、重试、并行请求优化
        - 适合大文件，无需一次性下载
    - 缺点：
        - 服务器必须配置正确的 CORS 和 `Accept-Ranges` 头
    - 示例：
    ```javascript
    const source = new UrlSource('https://example.com/video.mp4', {
      maxCacheSize: 16 * 1024 * 1024, // 16MB 缓存
      parallelism: 2,
    });
    ```

4. `FilePathSource`

    **核心用途**：从本地文件路径读取（仅 Node.js 环境）。
    - 支持：本地文件路径字符串（如 `./video.mp4`）
    - 典型场景：
        - Node.js 后端服务读取服务器上的媒体文件
    - 优点：
        - 直接访问文件系统，高效稳定
        - 支持范围请求
    - 缺点：
        - **仅 Node.js 可用，浏览器环境无法使用**
    - 示例（Node.js）：
    
        ```javascript
        const source = new FilePathSource('./video.mp4');
        ```

5. `StreamSource`

    **核心用途**：从 Node.js 流读取（仅 Node.js 环境）。
    - 支持：Node.js `Readable` 流
    - 典型场景：
        - 处理网络请求流、文件流
        - 从其他 API 获得的流数据
    - 优点：
        - 兼容 Node.js 生态
    - 缺点：
        - 不支持范围请求
        - 浏览器环境无法使用

6. `ReadableStreamSource`

    **核心用途**：从浏览器 `ReadableStream` 读取。
    - 支持：浏览器 `ReadableStream`（如 fetch 响应流）
    - 典型场景：
        - 流式下载的媒体数据
        - 从 `fetch(url).body` 直接读取
    - 优点：
        - 无需等待文件完全下载即可开始解析
        - 支持流的实时处理
    - 缺点：
        - 不支持范围请求，无法随机访问
    - 示例：

        ```javascript
        const response = await fetch(url);
        const source = new ReadableStreamSource(response.body);
        ```

7. `PathedSource`

    **核心用途**：所有带“路径”的源的基类（不直接使用）。
    - 继承自 `Source`
    - 是 `UrlSource`、`FilePathSource` 等的父类
    - 提供 `getPath()`、`setPath()` 等方法
    - 你一般不会直接实例化它，而是使用它的子类。

8. `CustomPathedSource`

    **核心用途**：自定义路径解析逻辑的基类（高级用法）。
    - 继承自 `PathedSource`
    - 允许你实现自己的路径处理逻辑
    - 典型场景：
        - 自定义协议（如 `myprotocol://`）
        - 从特殊服务获取媒体数据
    - 优点：
        - 高度可扩展
    - 缺点：
        - 需要实现所有必要的接口方法，复杂度高

#### 2. 代码实例

1. 代码

    ```html
    <!DOCTYPE html>
    <html>
    <head>
      <meta charset="utf-8">
      <title>Mediabunny 输入源 Input Sources 完整演示</title>
    </head>
    <body>
      <pre id="log"></pre>

      <script type="module">
        import {
          Input,
          ALL_FORMATS,
          BlobSource,
          UrlSource,
          BufferSource
        } from "../../js/mediabunny.1.42.mjs";

        const log = document.getElementById('log');
        const VIDEO_URL = "../../video/04.mp4";

        (async () => {
          log.textContent += "Mediabunny Input Sources 输入源演示开始\n\n";

          try {
        
            // 1. 【UrlSource】从网络 URL 读取（官方推荐）
            log.textContent += "━━━━━━━━ 1. UrlSource (网络URL) ━━━━━━━━\n";
            const urlSource = new UrlSource(VIDEO_URL, {
              maxCacheSize: 16 * 1024 * 1024,    // 16MB 缓存
              parallelism: 2,                   // 并行请求数
              getRetryDelay: (n) => Math.min(2**n, 16), // 指数退避重试
            });

            // 监听读取事件
            urlSource.on('read', ({ start, end }) => {
              log.textContent += `UrlSource 读取字节范围 [${start}, ${end})\n`;
            });

            // 切片：只读取前 10KB
    ```

### 1.2.3 初始化与销毁

1. 使用 `input.destroy()` 销毁输入源


    - 为什么需要释放:

        因为 Mediabunny 会占用：解码器、内存、网络连接、文件句柄。

        这些资源 JS 垃圾回收（GC）不会自动帮你释放，必须手动调用 dispose()。


    -  哪些资源会被 dispose() 释放？

        `dispose()` 一次性释放所有底层资源：

        - 停止所有网络请求
        - 关闭文件/Blob 引用
        - 释放视频/音频解码器
        - 清空解析缓存
        - 销毁轨道对象
        - 取消所有异步操作
        - 释放内存缓冲区

    - 官方为什么不自动释放？

        因为 **Input 是底层媒体解析库**，不是简单工具：
        - 你可能需要**长时间持有轨道**用于连续生成缩略图
        - 你可能需要**复用解码器**
        - 你可能需要**保持流连接**
        - 框架**不知道你什么时候用完**

2. 正确写法（官方唯一推荐）

    ```javascript
    let input;

    try {
        input = new Input({ source, formats: ALL_FORMATS });
        const duration = await input.computeDuration();
    } catch (err) {
        console.error(err);
    } finally {
        //  无论成功失败，必须释放
        if (input) input.dispose();
    }
    ```

## 1.3 轨道数据

### 1.3.1 轨道介绍

#### 1. 信息介绍

1. 轨道（Track）是什么？
    在媒体文件（MP4/WebM 等）里，**视频、音频、字幕是分开存储的流**，每一路流就叫一个 **Track（轨道）**。

    - 一个视频文件可以有：
        - 1 条视频轨（主画面）
        - 1～N 条音频轨（不同语言/配音）
        - 0～N 条字幕轨（中文/英文等）
    - Mediabunny 的 **Input** 负责把这些轨道解析出来，封装成结构化的 **InputTrack 对象**。

    一句话：**轨道 = 媒体文件里的一路独立数据流**。

    一句话：**轨道（Track）是媒体文件里的独立流（视频/音频/字幕）**，Mediabunny 把它们解析成带详细元数据的对象，供你读取、筛选、解码和处理。


2. Mediabunny 的轨道类型

从 `input.getTracks()` 拿到的是**所有轨道的数组**，按类型分为 3 大类：

- 视频轨道 InputVideoTrack 画面相关信息，最常用。

    **关键字段**：

    - `displayWidth` / `displayHeight`：宽高（像素）
    - `rotation`：旋转角度（0/90/180/270）
    - `codec`：编码格式（如 `avc1` / `vp9`）
    - `duration`：轨道时长（秒）
    - `frameRate`：帧率（FPS）

- 音频轨道 InputAudioTrack 声音相关信息。

    **关键字段**：
    - `sampleRate`：采样率（如 44100 Hz）
    - `numberOfChannels`：声道数（1=单声道，2=立体声）
    - `codec`：编码（`aac` / `opus`）
    - `duration`：时长

- 字幕轨道 InputSubtitleTrack 字幕/文本轨。

    - `language`：语言（`zh` / `en`）
    - `codec`：字幕格式（`srt` / `webvtt`）

3. 官方 API：如何获取轨道


    1. 获取所有轨道

        ```javascript
        const input = new Input({ source, formats: ALL_FORMATS });
        const tracks = await input.getTracks(); 
        // => InputTrack[]（包含视频+音频+字幕）
        ```

    2. 只拿视频/音频

        ```javascript
        const videoTracks = await input.getVideoTracks();   // 所有视频轨
        const audioTracks = await input.getAudioTracks();     // 所有音频轨

        const mainVideo = await input.getPrimaryVideoTrack();// 主视频轨
        const mainAudio = await input.getPrimaryAudioTrack();// 主音频轨
        ```

    3. 判断轨道能否被浏览器解码

        ```javascript
        if (await mainVideo.canDecode()) {
          console.log("该视频轨可以在当前浏览器播放");
        }
        ```


4. 轨道信息有什么用？
    1. **显示媒体信息**：分辨率、帧率、时长、编码格式。
    2. **选择性处理**：只转码视频轨，保留多语言音频轨。
    3. **解码/渲染**：用 `VideoSampleSink` 读取视频轨的每一帧。
    4. **轨道过滤**：去掉不需要的字幕轨/音频轨，减小文件体积。

### 1.3.2 通用轨道

#### 1. 通用信息介绍


在 Mediabunny 中，**轨道（Track）** 是媒体文件的基本逻辑单元，分为**视频轨、音频轨、字幕轨**三类。每个轨道都包含独立的**编码、时序、语言、码率**等元数据。`InputTrack` 是读取这些信息的核心API，可通过`Input.getTracks()`获取所有轨道实例。


1. 基础标识信息（同步属性）

    无需异步调用，直接读取轨道固有标识：

    | 属性 | 类型 | 说明 |
    |---|---|---|
    | `track.id` | `number` | 轨道全局唯一ID（文件内唯一） |
    | `track.number` | `number` | 同类型轨道内的序号（1开始，如第2条视频轨=2） |
    | `track.type` | `string` | 轨道类型：`video`/`audio`/`subtitle` |
    | `track.isVideoTrack()` | `boolean` | 是否为视频轨 |
    | `track.isAudioTrack()` | `boolean` | 是否为音频轨 |

    **代码示例**
    ```javascript
    for (const track of tracks) {
        log.textContent += `轨道ID:${track.id}, 类型:${track.type}, 序号:${track.number}`;
    }
    ```

2. 核心元数据（异步方法）

    需`await`调用，返回轨道详细属性。

    1. 基础描述信息

        | 方法 | 返回值 | 说明 |
        |---|---|---|
        | `getLanguageCode()` | `string` | ISO 639-2/T语言代码（如`eng`/`chi`，未知返回`und`） |
        | `getName()` | `string|null` | 轨道自定义名称（无则`null`） |
        | `getDisposition()` | `Object` | 轨道用途标记：`{default, dub, original, comment, lyrics, karaoke, forced, hearingImpaired, visualImpaired, cleanEffects}` |
        | `getBitrate()` | `number|null` | 峰值码率（bps，无则`null`） |
        | `getAverageBitrate()` | `number|null` | 平均码率（bps，无则`null`） |
        | `hasOnlyKeyPackets()` | `boolean` | 轨道是否全为关键帧（如I帧序列） |
        | `isLive()` | `boolean` | 是否为直播流（动态追加数据） |
        | `getLiveRefreshInterval()` | `number|null` | 直播流刷新间隔（秒，非直播返回`null`） |

        **代码示例**

        ```javascript
        const lang=await track.getLanguageCode();
        const disp=await track.getDisposition();
        log.textContent += `语言:${lang}, 默认轨道:${disp.default}`;
        ```

    2. 编解码器信息

        | 方法 | 返回值 | 说明 |
        |---|---|---|
        | `getCodec()` | `Object` | 编码格式：`{name, longName, type, subtype}`（如`h264`/`aac`） |
        | `getCodecParameterString()` | `string` | 编码参数（如`avc1.4D401E`） |
        | `canDecode()` | `boolean` | 当前浏览器是否支持解码该轨道 |

        **代码示例**

        ```javascript
        const codec=await track.getCodec();
        log.textContent += `编码:${codec.name}, 可解码:${await track.canDecode()}`;
        ```

    3. 时序与时长信息

        | 方法 | 返回值 | 说明 |
        |---|---|---|
        | `computeDuration()` | `number` | 精确时长（秒，遍历数据包计算） |
        | `getDurationFromMetadata()` | `number|null` | 元数据标注时长（秒，无则`null`） |
        | `getFirstTimestamp()` | `number|null` | 首帧时间戳（秒，无则`null`） |
        | `getTimeResolution()` | `number` | 时间分辨率（Hz，如`25`=25fps） |
        | `isRelativeToUnixEpoch()` | `boolean` | 时间戳是否基于Unix纪元（直播流常用） |

        **代码示例**

        ```javascript
        const duration=await track.computeDuration();
        log.textContent += `精确时长:${duration.toFixed(2)}s`;
        ```

    4. 数据包统计信息

        | 方法 | 返回值 | 说明 |
        |---|---|---|
        | `computePacketStats()` | `Object` | 数据包统计：`{packetCount, averagePacketRate, averageBitrate}` |

        - `packetCount`：数据包总数
        - `averagePacketRate`：平均包率（≈实际帧率FPS）
        - `averageBitrate`：平均码率（bps）

        **代码示例**
        ```javascript
        const stats=await track.computePacketStats();
        log.textContent += `包数:${stats.packetCount}, 帧率:${stats.averagePacketRate}`;
        ```

3. 完整调用流程

    1. **创建Input实例**（BlobSource/UrlSource）
    2. **获取所有轨道**：`const tracks=await input.getTracks()`
    3. **遍历轨道**，调用异步方法获取元数据
    4. **销毁资源**：`input.dispose()`（防止内存泄漏）

    **完整示例**

    ```javascript
    const input=new Input({ formats: ALL_FORMATS, source: new BlobSource(file) });
    const tracks=await input.getTracks();
    for (const track of tracks) {
        // 基础信息
        log.textContent += `轨道#${track.id} [${track.type}]`;
        // 元数据
        const lang=await track.getLanguageCode();
        const codec=await track.getCodec();
        const duration=await track.computeDuration();
        const stats=await track.computePacketStats();
        log.textContent += `语言:${lang}, 编码:${codec.name}, 时长:${duration.toFixed(2)}s, 帧率:${stats.averagePacketRate}`;
    }
    input.dispose();
    ```

4. 常见用途

    - **媒体信息展示**：播放器显示分辨率、帧率、码率、语言
    - **轨道筛选**：选择默认/英文/高清轨道
    - **兼容性判断**：过滤浏览器不支持的编码
    - **直播流处理**：检测动态流并获取刷新间隔
    - **元数据修复**：对比`computeDuration`与`getDurationFromMetadata`，修正时长错误

5. 注意事项

    1. **异步调用**：所有元数据方法均为异步，必须`await`
    2. **资源释放**：使用完`Input`后务必调用`dispose()`
    3. **大文件优化**：`computePacketStats`默认读取前50个包，速度快
    4. **兼容性**：`canDecode()`可判断浏览器是否支持H.265/AV1等编码

### 1.3.3 视频轨道专有信息

#### 1. 文档

`InputVideoTrack` 是 Mediabunny 中**视频轨道专用API**，继承自通用轨道 `InputTrack`，除基础元数据外，额外提供**分辨率、像素比、旋转、色彩、HDR、解码器配置**等视频专属信息，用于精准控制视频渲染与播放。



1. 视频核心尺寸信息（同步属性）

    无需异步调用，直接读取视频帧的原始/显示尺寸：

    | 属性 | 类型 | 说明 |
    |---|---|---|
    | `codedWidth` | `number` | **编码宽度**：视频帧原始编码像素宽度（未裁剪/未旋转） |
    | `codedHeight` | `number` | **编码高度**：视频帧原始编码像素高度 |
    | `squareWidth` | `number` | **方像素宽度**：校正像素比后、旋转前的宽度 |
    | `squareHeight` | `number` | **方像素高度**：校正像素比后、旋转前的高度 |
    | `displayWidth` | `number` | **显示宽度**：最终渲染宽度（校正像素比+旋转后） |
    | `displayHeight` | `number` | **显示高度**：最终渲染高度 |
    | `rotation` | `0｜90｜180｜270` | **顺时针旋转角度**：视频帧需旋转的角度 |
    | `pixelAspectRatio` | `{num:number,den:number}` | **像素宽高比**：像素形状（通常1:1，非正方形像素如DVD为4:3） |

    **关键区别**

    - **编码尺寸**：存储原始像素（如1920×1080）
    - **显示尺寸**：播放器实际渲染尺寸（如旋转90°后变为1080×1920）
    - **像素比**：影响拉伸（如2:1像素比会让画面横向拉伸）



2. 视频编码与渲染配置（异步方法）

    需`await`调用，返回视频解码、色彩、HDR等关键配置：

    1. 解码器配置

        | 方法 | 返回值 | 说明 |
        |---|---|---|
        | `getDecoderConfig()` | `Object` | **解码器配置**：含编码格式、SPS/PPS、分辨率、色彩空间等，供`VideoDecoder`直接解码 |

    2. 色彩与HDR信息

        | 方法 | 返回值 | 说明 |
        |---|---|---|
        | `getColorSpace()` | `Object` | **色彩空间**：`{primaries, transfer, matrix}`（如BT.709、BT.2020） |
        | `hasHighDynamicRange()` | `boolean` | **是否HDR**：`true`为HDR（如HDR10、Dolby Vision），`false`为SDR |

3. 帧率与数据包统计（异步方法）

    通过数据包计算实际帧率，避免元数据不准问题：

    | 方法 | 返回值 | 说明 |
    |---|---|---|
    | `computePacketStats(n?:number)` | `Object` | **数据包统计**：读取前n个包（默认50），返回`{packetCount,averagePacketRate,averageBitrate}` |
    | `averagePacketRate` | `number` | **平均帧率（FPS）**：实际播放帧率（优先用此值，比元数据准确） |


4. 完整代码示例（读取视频轨道信息）

    ```javascript
    import { Input, ALL_FORMATS, BlobSource } from "mediabunny";

    // 读取本地视频文件
    const file = document.querySelector('input[type="file"]').files[0];
    const input = new Input({
        formats: ALL_FORMATS,
        source: new BlobSource(file)
    });

    // 获取所有视频轨道
    const videoTracks = await input.getVideoTracks();
    for (const track of videoTracks) {
        // 1. 基础尺寸（同步）
        console.log("编码尺寸:", track.codedWidth, "×", track.codedHeight);
        console.log("显示尺寸:", track.displayWidth, "×", track.displayHeight);
        console.log("旋转角度:", track.rotation, "°");
        console.log("像素比:", track.pixelAspectRatio.num, ":", track.pixelAspectRatio.den);

        // 2. 编码与色彩（异步）
        const decoderConfig = await track.getDecoderConfig();
        const colorSpace = await track.getColorSpace();
        const isHdr = await track.hasHighDynamicRange();
        console.log("解码器配置:", decoderConfig);
        console.log("色彩空间:", colorSpace);
        console.log("HDR:", isHdr);

        // 3. 帧率统计（异步）
        const stats = await track.computePacketStats(100); // 读取前100包
        console.log("实际帧率:", stats.averagePacketRate, "FPS");
    }

    // 释放资源
    input.dispose();
    ```

5. 常见用途

    1. **播放器适配**：根据`displayWidth`/`displayHeight`/`rotation`自动调整画布尺寸与旋转
    2. **HDR/SDR切换**：通过`hasHighDynamicRange()`判断是否启用HDR渲染
    3. **兼容性解码**：`getDecoderConfig()`直接传入`VideoDecoder`，无需手动解析SPS/PPS
    4. **帧率校准**：用`averagePacketRate`替代元数据帧率，解决动态帧率/元数据错误问题
    5. **视频编辑**：获取原始编码尺寸与像素比，避免裁剪/拉伸失真

6. 注意事项

    1. **同步vs异步**：尺寸/旋转/像素比为同步属性；色彩、HDR、解码器配置为异步方法
    2. **资源释放**：`Input`使用完必须调用`dispose()`，防止内存泄漏
    3. **大文件优化**：`computePacketStats(100)`仅读前100包，速度快且足够准确
    4. **旋转处理**：`rotation`为视频固有属性，渲染时需应用对应旋转矩阵

### 1.3.4 音频轨道

#### 1. 文档

1. 概述

    **InputAudioTrack**（音频轨道）是 Mediabunny 中专门用于描述**音频流**的对象。
    它继承自通用轨道 `InputTrack`，并额外提供**声道数、采样率、解码器配置**等音频专属信息。

    这些信息常用于：
    - 音频播放器显示信息
    -  `Web Audio API` 处理
    - 音频解码兼容性判断
    - 转码、格式分析


2. 音频轨道专属 API（

    1.  `await track.getNumberOfChannels()`

        **获取音频声道数量**
        - 返回：`number`
        - 说明：
            - `1` = 单声道（Mono）
            - `2` = 立体声（Stereo）
            - `6` = 5.1 声道
            - `8` = 7.1 声道
    2. `await track.getSampleRate()`
        **获取音频采样率**
        - 返回：`number`（单位：Hz）
        - 常见值：
            - `44100` Hz（标准音乐）
            - `48000` Hz（视频常用）
            - `32000` / `22050` 等
    3. `await track.getDecoderConfig()`
        **获取浏览器原生音频解码器配置**
        - 返回：`object`
        - 用途：
            - 可直接传入浏览器 **WebCodecs AudioDecoder** 进行解码
            - 包含编码、采样率、声道、数据描述等底层信息

3. 完整 API 说明表格

    | API | 返回类型 | 说明 |
    |---|---|---|
    | `getNumberOfChannels()` | `number` | 声道数（1=单声道，2=立体声） |
    | `getSampleRate()` | `number` | 采样率（Hz），决定音频音质与精度 |
    | `getDecoderConfig()` | `object` | 浏览器解码器所需的完整配置 |


4. 使用场景（为什么要读取这些信息）
    - **显示音频信息**：播放器显示“立体声 48000Hz”
    - **解码音频**：使用 WebCodecs 播放/处理音频
    - **音质判断**：采样率越高音质越好
    - **声道判断**：判断是否为立体声
    - **兼容性检查**：判断浏览器能否播放该编码音频

    ```html
          log.textContent = `开始读取音视频轨道元数据...\n`;
          const url = `../../video/04.mp4`;

            const res = await fetch(url);
    ```
