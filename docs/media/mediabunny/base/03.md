# 三、写入信息

## 3.1 Output使用与格式

### 3.1.1 ouput的输入


1. 核心概念总览

    在 Mediabunny 里，**`Output` 是“容器”**，它由两部分组成：

    - **`format`：输出格式** → 决定文件的**封装格式/标准**（比如 MP4、MKV、HLS、FLAC），对应你第一张图里的列表。
    - **`target`：输出目标** → 决定数据**最终写到哪里**（内存、文件、流、HTTP 等），对应你第二张图里的列表。

    你写的这行代码：
    ```js
    const output = new Output({
        format: new Mp4OutputFormat(), // 封装格式：MP4
        target: new BufferTarget(),    // 输出目标：内存缓冲区
    });
    ```

    意思就是：
    > 创建一个 MP4 格式的输出，最终文件数据会写入内存缓冲区（而不是直接存到硬盘文件）。


2. OutputFormat（输出格式）分类解析

    | 类别 | 格式 | 用途说明 |
    | :--- | :--- | :--- |
    | **通用视频格式** | `Mp4OutputFormat` | 最常用，MP4 封装，兼容所有播放器 |
    | | `MovOutputFormat` | QuickTime 格式，和 MP4 很像，支持更多元数据 |
    | | `MkvOutputFormat` | 万能封装，支持多轨道、字幕、音轨 |
    | | `WebMOutputFormat` | Web 专用，VP9/AV1+Opus，浏览器原生支持 |
    | **流媒体格式** | `HlsOutputFormat` | HLS 直播/点播，生成 .m3u8 索引 + 分片 |
    | | `CmafOutputFormat` | 自适应流（DASH/HLS 通用），适合跨平台分发 |
    | | `MpegTsOutputFormat` | MPEG-TS 流，常用于直播流、IPTV |
    | **纯音频格式** | `Mp3OutputFormat` | 生成 MP3 音频文件 |
    | | `FlacOutputFormat` | 无损 FLAC 格式 |
    | | `WavOutputFormat` | 标准 PCM WAV 文件 |
    | | `OggOutputFormat` | Ogg 容器（一般装 Vorbis/Opus） |
    | **特殊/裸流格式** | `AdtsOutputFormat` | AAC ADTS 裸流，常用于直播推流 |
    | | `IsobmffOutputFormat` | 底层 ISO BMFF 格式，是 MP4 的基础 |

    **最常用的选择建议：**

    - 要生成普通视频文件：`Mp4OutputFormat`
    - 要做直播/流媒体：`HlsOutputFormat` 或 `MpegTsOutputFormat`
    - 只输出音频：`Mp3OutputFormat` / `FlacOutputFormat`
    - 要 Web 原生播放：`WebMOutputFormat`


3. OutputTarget（输出目标）分类解析


    | 类别 | 目标 | 用途说明 |
    | :--- | :--- | :--- |
    | **内存目标（无硬盘IO）** | `BufferTarget` | 把数据写入内存缓冲区，可直接拿到 ArrayBuffer，适合浏览器、前端处理 |
    | | `NullTarget` | 写入“黑洞”，数据直接丢弃，只用来测试编码/转封装逻辑 |
    | **文件/本地存储目标** | `FilePathTarget` | 直接写入本地文件路径（Node.js 环境用） |
    | **流/网络目标** | `StreamTarget` | 写入 Node.js 流（如 HTTP 响应、WebSocket、文件流） |
    | | `AppendOnlyStreamTarget` | 只能追加写入的流，适合直播场景 |
    | | `PathedTarget` / `RangedTarget` | 支持按路径/范围写入的高级流，用于 HLS/DASH 分片 |

    **你代码里的 `BufferTarget` 是最常用的前端目标：**
    - 它会把 MP4 数据全部写到内存的 `ArrayBuffer` 里
    - 后续你可以：
        - 转成 Blob 下载
        - 直接传给 MediaSource 播放
        - 上传到服务器

4. 关键组合场景推荐

    给你几个常见场景的 `format + target` 组合，直接用就行：

    | 场景 | 推荐 Format | 推荐 Target | 说明 |
    | :--- | :--- | :--- | :--- |
    | 前端生成 MP4 并下载 | `Mp4OutputFormat` | `BufferTarget` | 内存写入，前端无文件IO |
    | Node.js 生成 MP4 文件 | `Mp4OutputFormat` | `FilePathTarget` | 直接写入本地文件 |
    | 浏览器直播推流 | `HlsOutputFormat` | `StreamTarget` | 生成 m3u8 + 分片，推流到服务器 |
    | 只转码不保存 | 任意格式 | `NullTarget` | 测试编码逻辑，不写数据 |
    | 生成 WebM 供浏览器播放 | `WebMOutputFormat` | `BufferTarget` | 内存写入，转 Blob 直接播放 |

### 3.1.2 合成生命周期


1. Mediabunny Output 标准生命周期（必须按这个顺序）

    1. 创建 Output（编码器容器）
    2. 添加轨道（VideoSampleSource）
    3. 启动输出（output.start()）
    4. 写入 VideoSample 数据
    5. 完成封装（output.finalize()）
    6. 使用结果（播放/下载）+ 释放资源

2. 代码示例

    ```html
    <!DOCTYPE html>
    <html lang="zh-CN">
    
    <head>
      <meta charset="UTF-8">
      <title>Output 6大核心步骤</title>
    </head>
    
    <body>
      <video id="player" controls height="320" style="margin-top:20px"></video>
      <pre id="output"></pre>
    
      <script type="module">
        import {
          Input,
          ALL_FORMATS,
          UrlSource,
          VideoSampleSink,
          Output,
          Mp4OutputFormat,
          VideoSampleSource,
          BufferTarget
        } from "../../js/mediabunny.1.42.mjs";
    
        const outputEl = document.getElementById('output');
        const log = (msg) => outputEl.textContent += msg + '\n';
    
        // 测试视频
        const VIDEO_URL = "../../video/04.mp4";
    
        (async () => {
          try {
            log("1. 创建 编码器");
            const output = new Output({
              format: new Mp4OutputFormat(),
              target: new BufferTarget(),
            });
    
            log("2. 添加轨道");
            const videoSampleSource = new VideoSampleSource({ 
              codec: "avc", 
              bitrate: 1e6, // 1 Mbps	
            });
            output.addVideoTrack(videoSampleSource);
    
            log("3. 启动编码器...");
            await output.start();
    
            log("4. 写入数据包");
            const input = new Input({
              formats: ALL_FORMATS,
              source: new UrlSource(VIDEO_URL)
            });
            const videoTrack = await input.getPrimaryVideoTrack();
            const videoSink = new VideoSampleSink(videoTrack);
            for await (const sample of videoSink.samples()) {
              await videoSampleSource.add(sample);
              sample.close();
            }
    
            log("5. 完成编码...");
            await output.finalize();
    
            log("6. 资源使用\n");
            const arrayBuffer = output.target.buffer;
            const blobResult = new Blob([arrayBuffer], { type: "video/mp4" });
            const url = URL.createObjectURL(blobResult);
            player.src = url;
    
            player.addEventListener("loadedmetadata", () => {
              log(`播放器加载成功！视频时长: ${player.duration.toFixed(2)}s`);
            });
    
            log("全部流程执行完成！");
    
            // 释放input
            input.dispose();
    
          } catch (err) {
            log("错误：" + err.message);
            console.error(err);
          }
        })();
      </script>
    </body>
    </html>
    ```

## 3.2 媒体源

### 3.2.1 视频源

#### 1. 配置项说明

`VideoEncodingConfig` 是 **MediaBunny 所有内部编码视频源**的必选配置，用于定义视频编码格式、码率、画质、帧率、旋转裁剪、硬件加速等所有核心参数。

1. 完整类型定义

    ```typescript
    type VideoEncodingConfig = {
      // 基础必选配置
      codec: VideoCodec;
      bitrate: number | Quality;

      // 基础可选配置
      alpha?: 'discard' | 'keep';
      bitrateMode?: 'constant' | 'variable';
      latencyMode?: 'quality' | 'realtime';
      keyFrameInterval?: number;
      fullCodecString?: string;
      hardwareAcceleration?: 'no-preference' | 'prefer-hardware' | 'prefer-software';
      scalabilityMode?: string;
      contentHint?: string;
      sizeChangeBehavior?: 'deny' | 'passThrough' | 'fill' | 'contain' | 'cover';

      // 帧变换（缩放、旋转、裁剪、帧率、自定义处理）
      transform?: {
        width?: number;
        height?: number;
        fit?: 'fill' | 'contain' | 'cover';
        rotate?: 0 | 90 | 180 | 270;
        crop?: { left: number; top: number; width: number; height: number };
        frameRate?: number;
        process?: (sample: VideoSample) => MaybePromise<
          CanvasImageSource | VideoSample | (CanvasImageSource | VideoSample)[] | null
        >;
        force?: boolean;
      };

      // 回调事件
      onEncodedPacket?: (
        packet: EncodedPacket,
        meta: EncodedVideoChunkMetadata | undefined
      ) => unknown;
      onEncoderConfig?: (
        config: VideoEncoderConfig
      ) => unknown;
    };
    ```

2. 配置项详细说明

    - 2.1 必选基础配置

        | 配置项 | 类型 | 说明 |
        |--------|------|------|
        | **codec** | `VideoCodec` | **必选**<br>视频编码格式，决定**压缩算法、兼容性、画质、体积** |
        | **bitrate** | `number / Quality` | **必选**<br>目标码率（比特率），控制**视频清晰度 + 文件大小** |



        - 2.1.1 codec 完整支持列表（VideoCodec）
            
            `codec` 只能使用以下**固定字符串**，代表 MediaBunny 支持的所有视频编码：

            ```ts
            type VideoCodec = 'avc' | 'hevc' | 'vp8' | 'vp9' | 'av1';
            ```

            | 编码 | 全称 | 特点 / 用途 | 兼容性 |
            |------|------|-------------|--------|
            | **avc** | H.264 / AVC | 最通用、兼容性最高、速度快 |  全平台/全浏览器支持 |
            | **hevc** | H.265 / HEVC | 压缩率高、同画质体积更小 |  部分浏览器/设备有限制 |
            | **vp8** | VP8 | 开源、低复杂度、旧标准 |  通用 |
            | **vp9** | VP9 | 高清、高压缩、开源 |  现代浏览器 |
            | **av1** | AV1 | 新一代超高压编、免专利 |  高算力、部分设备支持 |


        - 2.1.2 bitrate 码率：作用、意义、大小影响
            1. 作用

                **码率 = 每秒视频数据量（单位：bps）**
                决定：
                - **清晰度**：码率越高 → 细节越丰富、越清晰
                - **体积**：码率越高 → 文件越大
                - **流畅度**：码率过高 → 播放卡顿、加载慢

            2. 数值意义（参考）
                - `1_000_000` = 1 Mbps
                - `500_000` = 500 kbps
                - `2_000_000` = 2 Mbps

            3.  不同大小的作用
                - **低码率（300k~800k）**：体积小、模糊、适合网络差
                - **标准码率（1M~2M）**：清晰、体积适中、**最常用**
                - **高码率（3M~8M）**：高清、细节好、体积大
                - **超高码率（10M+）**：无损级、体积巨大

        - 2.1.3 Quality 质量等级（固定枚举）

            | 枚举 | 含义 | 适用场景 |
            |------|------|----------|
            | **QUALITY_VERY_LOW** | 极差 | 极小体积、预览图级 |
            | **QUALITY_LOW** | 差 | 网络差、小尺寸视频 |
            | **QUALITY_MEDIUM** | 中等 | 常规视频、默认推荐 |
            | **QUALITY_HIGH** | 高 | 高清、发布使用 |
            | **QUALITY_VERY_HIGH** | 极高 | 超清、高质量输出 |


            ```ts
            bitrate: QUALITY_MEDIUM  // 自动分配合适码率
            ```
    - 2.2 通用可选配置

        | 配置项 | 类型 | 默认值 | 说明 |
        |--------|------|--------|------|
        | **alpha** | `discard / keep` | `discard` | 透明通道处理方式<br>- `discard`：丢弃透明，视频不透明<br>- `keep`：保留透明通道（需容器支持，如 WebM） |
        | **bitrateMode** | `constant / variable` | `variable` | 码率控制模式<br>- `constant`：恒定码率<br>- `variable`：可变码率（画质更好） |
        | **latencyMode** | `quality / realtime` | `quality` | 延迟模式<br>- `quality`：画质优先<br>- `realtime`：低延迟优先（直播/实时流） |
        | **keyFrameInterval** | `number` | `2` | 关键帧间隔（秒）<br>越小越利于拖拽，但文件体积越大 |
        | **fullCodecString** | `string` | 自动生成 | 完整编码字符串，如 `avc1.42001f`<br>不配置则自动生成，必须与 `codec` 匹配 |
        | **hardwareAcceleration** | `no-preference / prefer-hardware / prefer-software` | `no-preference` | 硬件加速策略<br>建议保持 `no-preference` 兼容性最强 |
        | **scalabilityMode** | `string` | - | SVC 可扩展编码模式（WebRTC 使用，浏览器支持极少） |
        | **contentHint** | `string` | - | 视频内容类型提示，如 `motion`/`text`，优化编码策略 |
        | **sizeChangeBehavior** | `deny / passThrough / fill / contain / cover` | `deny` | 帧尺寸变化时的适配策略<br>- `deny`：尺寸不一致直接报错<br>- `passThrough`：直接传递<br>- `fill/contain/cover`：拉伸/等比适配/裁剪填充 |

    - 2.3 transform 帧变换配置（缩放/旋转/裁剪/帧率）

        对视频帧**编码前**执行预处理，支持缩放、旋转、裁剪、改帧率、自定义滤镜。

        | 子配置项 | 类型 | 说明 |
        |----------|------|------|
        | **width** | `number` | 输出宽度（像素） |
        | **height** | `number` | 输出高度（像素） |
        | **fit** | `fill / contain / cover` | 宽高都设置时的适配模式<br> 与 `sizeChangeBehavior` 互斥 |
        | **rotate** | `0 / 90 / 180 / 270` | 顺时针旋转角度 |
        | **crop** | `{left,top,width,height}` | 裁剪区域（旋转后、缩放前执行） |
        | **frameRate** | `number` | 强制输出帧率（Hz） |
        | **process** | 函数 | 自定义帧处理：水印、滤镜、颜色调整、帧丢弃等 |
        | **force** | `boolean` | 强制执行变换流程（即使无配置） |

        **执行顺序**

        `旋转 → 裁剪 → 缩放/适配 → 帧率调整 → 自定义process`

    - 2.4 回调函数

        | 回调 | 说明 |
        |------|------|
        | **onEncodedPacket** | 每一帧编码完成后触发<br>可用于统计进度、监听编码数据 |
        | **onEncoderConfig** | 编码器初始化完成触发<br>可查看最终生成的完整编码字符串 |

3. 最兼容的标准配置

### 3.2.2 音频源

#### 1. 配置项


`AudioEncodingConfig` 是 **MediaBunny 所有内部编码音频源**的核心配置，用于定义音频编码格式、码率、声道、采样率、混音、音效处理等所有参数。

1. 完整类型定义

    ```typescript
    type AudioEncodingConfig = {
      // 基础配置
      codec: AudioCodec;
      bitrate?: number | Quality;
      bitrateMode?: 'constant' | 'variable';
      fullCodecString?: string;

      // 音频变换（混音、重采样、自定义处理）
      transform?: {
        numberOfChannels?: number;
        sampleRate?: number;
        process?: (sample: AudioSample) => MaybePromise<
          AudioSample | AudioSample[] | null
        >;
      };

      // 回调事件
      onEncodedPacket?: (
        packet: EncodedPacket,
        meta: EncodedAudioChunkMetadata | undefined
      ) => unknown;
      onEncoderConfig?: (
        config: AudioEncoderConfig
      ) => unknown;
    };
    ```

2. 配置项详细说明

    - 2.1 基础配置

        | 配置项 | 类型 | 默认值 | 说明 |
        |--------|------|--------|------|
        | **codec** | `AudioCodec` | — | **必选**<br>音频编码格式，如 `aac` / `mp3` / `opus` / `flac` 等<br>PCM 无压缩编码可省略 |
        | **bitrate** | `number / Quality` | 自动 | 目标码率（bps），如 `128000` = 128kbps<br>也可使用质量等级：`QUALITY_MEDIUM` |
        | **bitrateMode** | `constant / variable` | `variable` | 码率控制模式<br>- `constant`：恒定码率<br>- `variable`：动态码率（音质更好） |
        | **fullCodecString** | `string` | 自动生成 | 完整编码字符串，如 AAC 使用 `mp4a.40.2`<br>不配置则自动生成，必须与 `codec` 匹配 |


                
        - 2.1.1 AudioCodec 支持列表

            ```typescript
            type AudioCodec = 'aac' | 'mp3' | 'opus' | 'flac' | 'pcm_s16le' | 'pcm_f32le';
            ```

            | 编码 | 说明 | 兼容性 | 用途 |
            |------|------|--------|------|
            | **aac** | 最通用音频编码 | 全平台/全浏览器 | 视频配乐、音乐、直播 |
            | **mp3** | 通用压缩格式 | 全平台 | 音乐、低码率语音 |
            | **opus** | 低延迟高音质 | 现代浏览器 | 语音通话、直播 |
            | **flac** | 无损压缩 | 部分支持 | 高保真音乐 |
            | **pcm_s16le** | 16位 PCM 无压缩 | 全平台 | 录音、无损采集 |
            | **pcm_f32le** | 32位浮点 PCM | 全平台 | 专业音频处理 |

        - 2.1.2 Quality 质量等级（与视频通用）

            | 等级 | 说明 | 适用场景 |
            |------|------|----------|
            | `QUALITY_VERY_LOW` | 极差 | 极低码率语音 |
            | `QUALITY_LOW` | 差 | 电话音质 |
            | `QUALITY_MEDIUM` | 中等 | 默认推荐（128kbps） |
            | `QUALITY_HIGH` | 高 | 音乐、高音质 |
            | `QUALITY_VERY_HIGH` | 极高 | 无损/接近无损 |


    - 2.2 transform 音频变换配置

        编码前对音频进行预处理，支持**改声道、重采样、自定义音效处理**。

        | 子配置项 | 类型 | 说明 |
        |----------|------|------|
        | **numberOfChannels** | `number` | 输出声道数<br>1 = 单声道<br>2 = 立体声<br>可实现上混 / 下混 |
        | **sampleRate** | `number` | 输出采样率（Hz）<br>常见：`16000` / `32000` / `44100` / `48000` |
        | **process** | `函数` | 自定义音频处理<br>可做：音效、混音、静音检测、帧丢弃等<br>返回 `AudioSample` / 数组 / `null` |


    - 2.3 回调函数

        | 回调 | 说明 |
        |------|------|
        | **onEncodedPacket** | 每帧音频编码完成触发<br>可用于统计进度、监听编码数据 |
        | **onEncoderConfig** | 编码器初始化完成触发<br>可查看最终生成的完整编码字符串 |

3. 最常用标准配置（推荐直接使用）

    - AAC 立体声标准配置（100%兼容）

        ```javascript
        const audioConfig = {
            codec: "aac",
            bitrate: 128000,        // 128kbps
            bitrateMode: "variable",
            fullCodecString: "mp4a.40.2",
            transform: {
                numberOfChannels: 2,  // 立体声
                sampleRate: 44100     // 标准采样率
            },
            onEncodedPacket: (packet) => {},
            onEncoderConfig: (config) => {}
        };
        ```

    - OPUS 低延迟语音配置

        ```javascript
        const audioConfig = {
            codec: "opus",
            bitrate: 64000,
            bitrateMode: "constant",
            transform: {
                numberOfChannels: 1,
                sampleRate: 16000
            }
        };
        ```

    - 使用场景速查

        | 场景 | 推荐配置 |
        |------|----------|
        | 视频配乐 | AAC + 128kbps + 44100Hz + 立体声 |
        | 直播语音 | OPUS + 64kbps + 16000Hz + 单声道 |
        | 高保真音乐 | FLAC + 无损 + 48000Hz |
        | 录音采集 | PCM + 无压缩 + 16bit |

### 3.2.3 字幕源

#### 1. 音频配置


1. 字幕源（Subtitle Source）概述

    - 作用：**向 Output 输出字幕轨道数据**
    - 所有字幕源都继承自抽象类 `SubtitleSource`
    - 当前 MediaBunny 提供的字幕源：**`TextSubtitleSource`**
    - 支持格式：**WebVTT（最通用、浏览器全支持）**


2. TextSubtitleSource 说明

    用于将 **WebVTT 格式文本字幕** 送入输出轨道。

    - 2.1 导入
        ```js
        import { TextSubtitleSource } from 'mediabunny';
        ```

    - 2.2 创建实例
        ```js
        const subtitleSource = new TextSubtitleSource('webvtt');
        ```

    - 2.3 添加字幕（两种方式）


        - 方式 1：一次性添加完整字幕（推荐）

            ```js
            const vttText = `
            WEBVTT

            00:00:00.000 --> 00:00:02.000
            这是第一行字幕

            00:00:02.500 --> 00:00:05.000
            这是第二行字幕
            `;

            await subtitleSource.add(vttText);
            subtitleSource.close(); // 必须关闭
            ```

        - 方式 2：分块添加

            ```js
            await subtitleSource.add('WEBVTT\n\n');
            await subtitleSource.add('00:00:00.000 --> 00:00:02.000\n你好\n\n');
            ```

3. WebVTT 字幕格式规则（必须遵守）

    1. 必须以 **`WEBVTT`** 开头
    2. 时间格式：`00:00:00.000 --> 00:00:00.000`
    3. 一个字幕块不能跨多个 chunk
    4. 可以添加对齐格式：

    ```
    00:00:00.000 --> 00:00:02.000 align:center
    居中显示字幕
    ```
4. 目前的存在的问题

    1. 只能嵌入 webm与 mkv 中，像mp4是加入不进去的
    2. 就算加进去了，web页面中video也是播放不了，只能使用本地的播放器查看

        const loadVideoFramesNative = async (videoUrl) => {
          return new Promise((resolve, reject) => {
            const video = document.createElement('video');
            video.muted = true;

            video.onloadedmetadata = async () => {
              const width = video.videoWidth;
              const height = video.videoHeight;
              const duration = video.duration;
              const fps = 30;
              const totalFrames = Math.floor(duration * fps);
              const frameDuration = 1 / fps;

              const canvas = document.createElement('canvas');
              const ctx = canvas.getContext('2d');
              canvas.width = width;
              canvas.height = height;

              const frames = [];
              video.currentTime = 0;

              video.ontimeupdate = async () => {
                const currentTime = video.currentTime;
                ctx.drawImage(video, 0, 0, width, height);
                const bitmap = await createImageBitmap(canvas);

                frames.push({
                  data: bitmap,
                  timestamp: currentTime,
                  duration: frameDuration
                });

                const nextTime = currentTime + frameDuration;
                if (nextTime >= duration) {
                  video.pause();
                  resolve({ frames, width, height, duration });
                  return;
                }
                video.currentTime = nextTime;
              };
            };

            video.src = videoUrl;
            video.play();

            });

	1. 代码理解

		1. **逐帧获取视频画面**
