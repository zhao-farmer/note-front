# 二、Service Worker

Service Worker（服务工作者）是一种**可编程的网络代理（network proxy）**，运行在浏览器后台，独立于网页主线程，主要用于**拦截和处理网络请求、实现离线缓存、推送通知、后台同步**等功能。它是构建 **PWA（渐进式 Web 应用）** 的核心技术之一。

## 1. 遇到的问题

默认页面一直被劫持，显示不了真正的页面

![](/other/knowledge/javascript/003.png)

## 2. Service Worker 的核心特性

| 特性 | 说明 |
|------|------|
| **运行在后台** | 不依赖页面是否打开，即使关闭标签页也能运行（有限制） |
| **事件驱动** | 响应 `install`、`activate`、`fetch` 等事件 |
| **必须通过 HTTPS** | 出于安全考虑（本地 `localhost` 例外） |
| **作用域限制** | 只能控制其注册路径下的页面（如 `/sw.js` 默认控制 `/` 下所有页面） |
| **异步 & Promise** | 所有操作基于 Promise，不能使用同步 API |


## 3. 基本使用步骤

### 3.1 注册 Service Worker（在主页面 JS 中）

```js
// main.js 或 index.html 中
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js')
      .then(registration => {
        console.log('SW 注册成功:', registration.scope);
      })
      .catch(error => {
        console.error('SW 注册失败:', error);
      });
  });
}
```

> 建议在 `window.load` 后注册，避免影响首屏加载。


### 3.2 编写 Service Worker 文件（`sw.js`）

放在网站根目录（或指定路径），例如：

```js
// sw.js

const CACHE_NAME = 'my-app-v1';
const urlsToCache = [
  '/',
  '/index.html',
  '/styles/main.css',
  '/scripts/app.js',
  '/images/logo.png'
];

// 安装阶段：缓存静态资源
self.addEventListener('install', event => {
  console.log('SW 安装中...');
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then(cache => {
        console.log('缓存静态资源');
        return cache.addAll(urlsToCache);
      })
      .then(() => self.skipWaiting()) // 立即激活（可选）
  );
});

// 激活阶段：清理旧缓存
self.addEventListener('activate', event => {
  console.log('SW 激活中...');
  const cacheWhitelist = [CACHE_NAME];
  event.waitUntil(
    caches.keys().then(cacheNames => {
      return Promise.all(
        cacheNames.map(cacheName => {
          if (!cacheWhitelist.includes(cacheName)) {
            console.log('删除旧缓存:', cacheName);
            return caches.delete(cacheName);
          }
        })
      );
    }).then(() => self.clients.claim()) // 立即接管页面（可选）
  );
});

// 拦截网络请求，实现缓存优先策略
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request)
      .then(response => {
        // 缓存命中则返回缓存，否则走网络
        return response || fetch(event.request);
      })
      .catch(() => {
        // 可选：返回兜底页面（如离线页）
        if (event.request.destination === 'document') {
          return caches.match('/offline.html');
        }
      })
  );
});
```


## 4. 调试技巧

1. **Chrome DevTools → Application → Service Workers**
   - 查看已注册的 SW
   - 手动 **Update / Unregister**
   - 勾选 **"Bypass for network"** 跳过 SW 调试

2. **强制更新 SW**
   - 修改 `sw.js` 内容（哪怕加个空格）
   - 浏览器会触发 `install` 事件（因为文件哈希变了）

3. **查看缓存**
   - DevTools → Application → Cache Storage


## 5. 注意事项

-  **不能访问 DOM**（运行在独立线程）
-  **不能使用 localStorage、XHR（需用 fetch）**
-  可使用 `caches`、`indexedDB`、`fetch`、`postMessage`
-  **更新机制**：只有当 `sw.js` 内容变化时才会触发更新
-  **及时清理旧缓存**，避免占用用户存储空间


## 6. 高级用法详解


### 6.1 缓存策略


| 策略 | 说明 | 适用场景 |
|------|------|--------|
| **Cache First（缓存优先）** | 先查缓存，没有再请求网络 | 静态资源（JS/CSS/图片） |
| **Network First（网络优先）** | 先请求网络，失败再用缓存 | 动态内容（API 数据） |
| **Cache Only** | 只使用缓存 | 离线兜底 |
| **Network Only** | 只走网络（默认行为） | 敏感数据 |
| **Stale-While-Revalidate** | 先返回缓存，同时后台更新缓存 | 平衡速度与新鲜度 |


```ts
// sw.js（带说明）
const CACHE_NAME = 'my-app-cache-v1';

self.addEventListener('fetch', (event: FetchEvent) => {
  const { request } = event;

  // 注意：以下四种策略不能同时使用！
  // 实际项目中应根据 URL 或资源类型选择一种策略。

  // ────────────────────────────────────────
  // 缓存优先（Cache First）
  //  适用：静态资源（JS/CSS/图片/字体）
  //  风险：内容长期不更新（需配合版本号或 hash）
  // ────────────────────────────────────────
  event.respondWith(
    caches.match(request).then(cached => cached || fetch(request))
  );

  // ────────────────────────────────────────
  // 网络优先（Network First）
  // 适用：动态内容（如用户数据、新闻列表）
  // 风险：离线时若无缓存则失败
  // ────────────────────────────────────────
  event.respondWith(
    fetch(request).catch(() => caches.match(request))
  );

  // ────────────────────────────────────────
  // 仅缓存（Cache Only）
  // 适用：完全离线场景（如离线游戏资源）
  // 风险：未缓存的请求直接失败
  // ────────────────────────────────────────
  event.respondWith(caches.match(request));

  // ────────────────────────────────────────
  // 网络优先 + 更新缓存（Stale-While-Revalidate）
  // 适用：HTML 页面、非敏感 API（平衡速度与新鲜度）
  // 注意：必须 clone() 响应，因为 Response 是不可重用的流
  // ────────────────────────────────────────
  event.respondWith(
    fetch(request)
      .then(response => {
        if (!response || response.status !== 200 || response.type !== 'basic') {
          return response; // 不缓存非成功或跨域响应
        }
        const responseClone = response.clone();
        caches.open(CACHE_NAME).then(cache => cache.put(request, responseClone));
        return response;
      })
      .catch(() => caches.match(request))
  );
});
```

>  **重要提醒**：
> - 一个 `fetch` 事件只能调用 **一次 `event.respondWith()`**。
> - 上述四种策略应通过 `if` 分支按需使用，**不能并列写在一起**（否则会报错）。
> - 推荐使用 [Workbox](https://developers.google.com/web/tools/workbox) 管理策略，避免手写错误。

### 6.2 后台同步

```ts
// ===== 主线程（app.js）=====
if ('serviceWorker' in navigator && 'SyncManager' in window) {
  navigator.serviceWorker.ready
    .then((registration: ServiceWorkerRegistration) => {
      // 注册一个名为 'sync-data' 的同步任务
      return registration.sync.register('sync-data');
    })
    .catch(err => console.warn('后台同步注册失败:', err));
}

// ===== Service Worker（sw.js）=====
self.addEventListener('sync', (event: SyncEvent) => {
  if (event.tag === 'sync-data') {
    // event.waitUntil() 告诉浏览器：任务正在进行中
    event.waitUntil(syncData());
  }
});

async function syncData(): Promise<void> {
  try {
    const offlineData = await getOfflineData(); // 从 IndexedDB 获取
    await sendToServer(offlineData);           // 发送到后端
    await clearOfflineData();                  // 清理已同步数据
  } catch (err) {
    console.error('同步失败，浏览器稍后将重试:', err);
    // 不要在这里 re-throw 错误，否则浏览器可能停止重试
  }
}

// 辅助函数示例（需自行实现）
async function getOfflineData(): Promise<any[]> {
  // 使用 idb 库或原生 IndexedDB
  return []; 
}

async function sendToServer(data: any[]): Promise<Response> {
  return fetch('/api/sync', {
    method: 'POST',
    body: JSON.stringify(data),
    headers: { 'Content-Type': 'application/json' }
  });
}
```

> **限制与兼容性**：
> - **仅 Chrome/Edge 支持**，Safari 和 Firefox 尚未实现。
> - 同步任务由浏览器在**网络恢复且设备空闲时触发**，非实时。
> - 用户关闭标签页后仍可运行（但非永久后台）。


### 6.3 推送通知

```ts
// ===== 主线程（请求权限 + 订阅）=====
Notification.requestPermission().then(permission => {
  if (permission === 'granted') {
    navigator.serviceWorker.ready
      .then((registration: ServiceWorkerRegistration) => {
        // applicationServerKey 必须是 Uint8Array 格式的 VAPID 公钥
        const applicationServerKey = urlBase64ToUint8Array(
          'BLJx9...你的公钥...' // 来自后端生成
        );
        return registration.pushManager.subscribe({
          userVisibleOnly: true, // 必须为 true（规范要求）
          applicationServerKey
        });
      })
      .then(subscription => {
        // 将 subscription 发送给后端保存（用于后续推送）
        return fetch('/api/save-subscription', {
          method: 'POST',
          body: JSON.stringify(subscription),
          headers: { 'Content-Type': 'application/json' }
        });
      })
      .catch(err => console.error('订阅失败:', err));
  }
});

// Base64Url → Uint8Array 工具函数
function urlBase64ToUint8Array(base64: string): Uint8Array {
  const padding = '='.repeat((4 - base64.length % 4) % 4);
  const b64 = (base64 + padding).replace(/-/g, '+').replace(/_/g, '/');
  const rawData = atob(b64);
  return Uint8Array.from([...rawData].map(char => char.charCodeAt(0)));
}

// ===== Service Worker（接收推送并显示）=====
self.addEventListener('push', (event: PushEvent) => {
  let data = { title: '新消息', body: '' };
  
  if (event.data) {
    try {
      data = event.data.json(); // 推荐使用 JSON
    } catch {
      data.body = event.data.text(); // 回退到文本
    }
  }

  const options: NotificationOptions = {
    body: data.body,
    icon: '/icons/icon-192.png',
    badge: '/icons/badge-72.png', // Android 通知栏小图标
    tag: 'default',               // 相同 tag 的通知会替换
    renotify: true                // 即使已存在通知也发出声音
  };

  event.waitUntil(
    self.registration.showNotification(data.title, options)
  );
});

// 用户点击通知时的处理
self.addEventListener('notificationclick', (event: NotificationEvent) => {
  event.notification.close();
  event.waitUntil(
    clients.matchAll({ type: 'window', includeUncontrolled: true })
      .then(clientList => {
        const url = '/'; // 跳转地址
        if (clientList.length > 0) {
          clientList[0].focus?.();
        } else {
          clients.openWindow?.(url);
        }
      })
  );
});
```

> 🔐 **安全与部署要求**：
> - 必须通过 **HTTPS**（localhost 除外）
> - 需要 **VAPID 密钥对**（可用 Node.js 的 `web-push` 库生成）
> - 后端推送时需使用相同私钥签名
> - iOS Safari 使用 Apple Push Notification service (APNs)，机制不同

### 7.1 `index.html` —— 主页面 + 注册 Service Worker

  <p>当前状态：<span class="status" id="status">正在加载...</span></p>
  <p>尝试断网后刷新页面，看看是否仍能访问！</p>

  <script>
    // 注册 Service Worker
    if ('serviceWorker' in navigator) {

### 7.2 `sw.js` —— Service Worker：缓存首页和离线页

```js
// sw.js

const CACHE_NAME = 'pwa-offline-v1';
const urlsToCache = [
  '/',
  '/index.html',
  '/offline.html'
];

// 安装时缓存关键资源
self.addEventListener('install', (event) => {
  console.log('[SW] 安装中...');
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then(cache => {
        console.log('[SW] 缓存静态资源');
        return cache.addAll(urlsToCache);
      })
      .then(() => self.skipWaiting()) // 立即激活
  );
});

// 激活时清理旧缓存（可选）
self.addEventListener('activate', (event) => {
  console.log('[SW] 激活中...');
  event.waitUntil(self.clients.claim()); // 立即接管页面
});

// 拦截请求，实现离线兜底
self.addEventListener('fetch', (event) => {
  // 只处理 GET 请求（避免干扰 POST 等）
  if (event.request.method !== 'GET') return;

  event.respondWith(
    caches.match(event.request).then(cachedResponse => {
      if (cachedResponse) {
        return cachedResponse; // 缓存命中
      }

      // 否则走网络
      return fetch(event.request).catch(() => {
        // 网络失败 → 返回离线页面（仅对 HTML 文档）
        if (event.request.destination === 'document') {
          return caches.match('/offline.html');
        }
        // 其他资源（如图片、JS）直接失败
        return Response.error();
      });
    })
  );
});
```

### 7.4 如何运行？

- 方法 1：使用本地 HTTP 服务器（推荐）

    因为 Service Worker **不能在 `file://` 协议下运行**，必须通过 HTTP。

    - 使用 Bun（如果你已安装）：

        ```bash
        bun run index.html
        # 或
        bun serve .
        ```

    - 使用 Python（快速启动）：

        ```bash
        # Python 3
        python -m http.server 8000
        ```

        然后访问：http://localhost:8000

    - 使用 Node.js（npx）：

        ```bash
        npx serve
        ```

- 方法 2：部署到线上（如 GitHub Pages、Vercel、Netlify）
    - 将这三个文件推送到仓库
    - 启用 HTTPS（这些平台默认支持）
    - 访问你的域名即可体验完整 PWA 功能


### 7.5 验证离线功能

1. 首次访问网站（确保 SW 安装成功）
2. 打开 Chrome DevTools → Application → Service Workers → 勾选 **"Offline"**
3. 刷新页面 → 应显示 `index.html`
4. 访问一个不存在的页面（如 `/abc`）→ 应显示 `offline.html`
