  1. 下载并安装

# 验证结果（重开cmd）

  2. 常用命令

    bun --version                    # 查看版本
bun --help                       # 查看帮助
bun install                      # 安装依赖
bun add <pkg>                    # 添加包
bun remove <pkg>                 # 移除包
bun run <script>                 # 运行脚本
bun test                         # 运行测试
bun build <entry>                # 打包项目
bun upgrade                      # 更新 Bun
bun completions                  # 启用自动补全

  3. 注意事项

    • 兼容性：Bun 与大部分 Node.js API 兼容，但并非 100%。复杂项目建议逐步迁移。
    • 原生模块：Bun 不支持 Node.js 原生插件（如 .node 文件），但支持 WASM。
    • 生态系统：Bun 生态仍在快速发展，部分 npm 包可能存在兼容问题。

2.2.1 路由

Next.js在 App Router 的基础上进一步优化了路由系统，强化了 React Server Components集成，并对分组路由、动态路由、并行路由等提供了更清晰的语义和更好的开发体验。

下面针对 Next.js 中的三种核心路由模式进行详细说明：基础路由、动态路由、分组路由，全部基于 App Router（app/ 目录）。

  1. 基础路由（Basic Routes）

    • 文件结构映射 URL

      文件路径对应 URL
      app/page.tsx/
      app/about/page.tsx/about
      app/dashboard/settings/page.tsx/dashboard/settings

    • 示例：创建 About 页面

      // app/about/page.tsx
export default function AboutPage() {
    return (
        <div>
            <h1>About Us</h1>
            <p>Welcome to our Next.js app!</p>
        </div>
    );
}

    访问 http://localhost:3000/about 即可看到页面。

    特性：

    • 自动代码分割（每个页面独立 chunk）
    • 默认服务端渲染（SSR），支持流式响应（Streaming SSR）

  2. 动态路由

    用于匹配未知参数的路径，如文章详情、用户主页等。

    • 语法：用方括号 [param] 包裹

      app/
└── blog/
    └── [slug]/
        └── page.tsx   → 匹配 /blog/hello, /blog/next-15-is-great

    • 获取动态参数

      在 page.tsx 中通过 params props 获取：

      // app/blog/[slug]/page.tsx
type Props = {
params: { slug: string };
};

export default function BlogPost({ params }: Props) {
return <h1>Blog Post: {params.slug}</h1>;
}

    • 多段动态路由

      app/shop/[category]/[productId]/page.tsx
→ /shop/electronics/123

      type Props = {
  params: { category: string; productId: string };
};

    • 可选动态段

    • [...slug]/page.tsx → Catch-all（匹配任意深度，如 /post/a/b/c）

      • params.slug 是数组：['a', 'b', 'c']

    • [[...slug]]/page.tsx → 可选 Catch-all（也匹配 /post 本身）

  3. 分组路由

    • 目的

      • 逻辑分组路由（不影响 URL 结构）
      • 共享不同布局（例如：营销页 vs 后台页）
      • 组织大型项目代码

    • 语法：用圆括号 (group) 包裹目录名

      圆括号内的名称不会出现在 URL 中！

      • 示例：区分“营销站点”和“管理后台”

        app/
├── (marketing)/
│   ├── layout.tsx      // 营销站通用布局（含 Header/Footer）
│   ├── page.tsx        → /
│   └── about/page.tsx  → /about
│
├── (admin)/
│   ├── layout.tsx      // 后台布局（含侧边栏）
│   └── dashboard/
│       └── page.tsx    → /dashboard
│
└── layout.tsx          // 全局根布局（可选）

      最终 URL：

      • / → 渲染 (marketing)/page.tsx + (marketing)/layout.tsx
      • /dashboard → 渲染 (admin)/dashboard/page.tsx + (admin)/layout.tsx

      优势：

      • / 和 /dashboard 使用完全不同的布局，但 URL 干净无前缀（如不用 /admin/dashboard）
      • 避免创建无意义的 URL 段（如 /app/dashboard）

    • 分组路由 + 动态路由组合

      app/
└── (user)/
    └── profile/
        └── [id]/
            └── settings/
                └── page.tsx   → /profile/123/settings

      即使放在 (user) 分组中，URL 仍是 /profile/123/settings，分组名被忽略。

  4. 实用技巧（Next.js 15 新特性）

    1. generateStaticParams() 静态生成动态页

      // app/blog/[slug]/page.tsx
export async function generateStaticParams() {
  const posts = await fetchPosts(); // 从 CMS 获取
  return posts.map(post => ({ slug: post.slug }));
}
// 构建时预渲染所有博客页（SSG）

    2. not-found.tsx 自定义 404

      app/
└── not-found.tsx   // 全局 404 页面

      在动态路由中手动触发：

      if (!post) notFound(); // from 'next/navigation'

    3. 路由拦截 —— 用于模态框

      用 (.)、(..)、(...) 拦截上级路由，常用于图片预览、登录弹窗等。

      app/
├── photo/
│   └── [id]/
│       └── page.tsx
└── (.)photo/         // 拦截 /photo/123，但以模态形式展示
    └── [id]/
        └── page.tsx

  5. 常见误区

    错误做法正确做法
    在 app/ 下写 index.tsx必须用 page.tsx
    用 (group) 做 URL 前缀分组名不会出现在 URL 中
    在服务端组件中用 useRouter()应使用 params 和 searchParams props

  6. 总结：Next.js 路由最佳实践

    路由类型用途文件示例
    基础路由静态页面app/about/page.tsx
    动态路由参数化页面app/post/[id]/page.tsx
    分组路由逻辑隔离 + 多布局app/(admin)/dashboard/page.tsx

    建议：

    • 用 分组路由 替代 URL 前缀来区分应用区域（如前台/后台）
    • 动态路由配合 generateStaticParams 实现 SSG
    • 所有数据获取优先放在 服务端组件 中（无需 useEffect）

2.2.2 布局

在 Next.js 中，布局（Layout）系统是 App Router 的核心特性之一，它基于 React Server Components，提供自动嵌套、流式渲染、布局复用、错误隔离等能力。相比旧版 Pages Router，布局更直观、性能更好、功能更强。

  1. 基础布局

    每个 Next.js 应用必须有一个根布局，定义 <html> 和 <body>。

    // app/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="zh-CN">
      <body>
        {children} {/* 所有页面内容将插入此处 */}
      </body>
    </html>
  );
}

    注意：

    • 文件名必须是 layout.tsx（或 .js）
    • 必须包含 <html> 和 <body> 标签（否则报错）
    • 默认是 服务端组件（Server Component）

  2. 嵌套布局

    通过在子目录中添加 layout.tsx，实现自动嵌套，无需手动导入。

    • 项目结构示例

      app/
├── layout.tsx                → 根布局（<html><body>）
├── page.tsx                  → 首页 /
│
├── dashboard/
│   ├── layout.tsx            → 仪表盘专属布局
│   ├── page.tsx              → /dashboard
│   └── settings/
│       └── page.tsx          → /dashboard/settings
│
└── marketing/
    ├── layout.tsx            → 营销页布局（不同 Header/Footer）
    └── pricing/page.tsx      → /pricing

    • 示例：Dashboard 布局

      // app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div className="dashboard-layout">
      <aside>侧边栏菜单</aside>
      <main>{children}</main> {/* /dashboard 和 /dashboard/settings 共享此布局 */}
    </div>
  );
}

    渲染 /dashboard/settings 时，实际结构为：

    RootLayout
└── DashboardLayout
    └── SettingsPage

  3. 分组路由 + 独立布局（推荐架构）

    使用 路由分组 (group) 实现逻辑隔离 + 不同布局，且不影响 URL。

    app/
├── (marketing)/
│   ├── layout.tsx      // 营销站布局（含 Hero/Header/Footer）
│   ├── page.tsx        → /
│   └── about/page.tsx  → /about
│
├── (app)/
│   ├── layout.tsx      // 应用内部布局（含导航栏/侧边栏）
│   └── dashboard/
│       └── page.tsx    → /dashboard
│
└── layout.tsx          // 根布局

    效果：

    • / 和 /about 使用营销布局
    • /dashboard 使用应用布局
    • URL 干净无前缀（如不是 /app/dashboard）

  4. 高级布局特性

  5. 布局中的数据获取（Server-only）

    布局可以直接 fetch 数据（服务端执行）：

    // app/(app)/layout.tsx
async function getUser() {
  const res = await fetch('https://api.example.com/user', {
    cache: 'force-cache' // 或 'no-store'（动态数据）
  });
  return res.json();
}

export default async function AppLayout({ children }: { children: React.ReactNode }) {
  const user = await getUser(); // 安全！在服务端执行

  return (
    <div>
      <header>Welcome, {user.name}!</header>
      {children}
    </div>
  );
}

    优势：用户信息在 HTML 中直出，无需客户端水合（Hydration）。

  6. 布局间共享状态？—— 不推荐！

    • 布局是 Server Component，不能使用 useState、useContext（除非标记 'use client'）
    • 不要试图在布局中管理全局状态（如主题、用户登录态）

    正确做法：

    • 用户状态：通过服务端 fetch + cookies 获取
    • 主题切换：用 'use client' 的 Provider 包裹 {children}
    // app/layout.tsx
import { ThemeProvider } from './components/theme-provider';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        {/* 客户端 Provider 只包裹 children */}
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  );
}

  7. 错误与加载状态隔离

    • 每个布局可配独立的 error.tsx 和 loading.tsx
    • 子路由出错/加载，不会影响父布局
    app/
└── dashboard/
    ├── layout.tsx
    ├── loading.tsx     → 进入 /dashboard 时显示
    ├── error.tsx       → /dashboard 内部错误时显示
    └── page.tsx

  8. 元数据（Metadata）在布局中定义

    Next.js 推荐在布局中设置 SEO 信息：

    // app/layout.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'My App',
  description: 'A Next.js application',
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>{children}</body>
    </html>
  );
}

    支持动态 metadata（函数形式）：

    export async function generateMetadata({ params }) {
  return { title: `Post ${params.id}` };
}

  9. 常见问题与最佳实践

    问题解决方案
    如何跳过某层布局？用 路由分组 (group) 创建独立布局树
    布局能访问 URL 参数吗？不能直接访问，但可通过 children 的 page.tsx 传递（不推荐）；建议在页面组件中处理
    多个 layout.tsx 冲突？Next.js 自动按目录深度嵌套，不会冲突
    需要全局状态（如用户）？在根布局中 fetch 用户数据，通过 props 传递给客户端 Provider

  10. 完整示例：多布局应用结构

    app/
├── layout.tsx                 # 根布局（<html><body> + 全局 metadata）
│
├── (site)/
│   ├── layout.tsx             # 营销站布局（Header/Footer）
│   ├── page.tsx               → /
│   └── blog/
│       ├── [slug]/
│       │   └── page.tsx       → /blog/hello
│       └── layout.tsx         # 博客子布局（带侧边栏）
│
├── (app)/
│   ├── layout.tsx             # 应用布局（需登录）
│   └── dashboard/
│       ├── layout.tsx         # 仪表盘布局（带导航）
│       └── page.tsx           → /dashboard
│
├── not-found.tsx              # 全局 404
└── global-error.tsx           # 全局错误（客户端）

2.2.3 模块化架构

你提出的目录结构是 Next.js 模块化架构（Modular Architecture） 的一种优秀实践，特别适合中大型项目。它将功能按 业务域（Domain） 划分（如 home、auth、product），每个模块内部自包含（UI、API、逻辑、类型等），极大提升可维护性、可测试性和团队协作效率。

  1. 模块化架构核心思想

    原则说明
    高内聚每个模块（如 home/）包含完成该功能所需的一切
    低耦合模块间通过清晰接口通信，避免直接依赖内部实现
    可复用公共逻辑抽离到 shared/ 或 lib/
    可测试每个模块可独立单元测试或 E2E 测试

  2. 推荐项目结构（Next.js + App Router）

    /
├── app/                     # Next.js App Router 入口（路由）
│   ├── (marketing)/
│   │   ├── page.tsx         → 引用 src/modules/home
│   │   └── layout.tsx
│   └── (app)/
│       └── dashboard/
│           └── page.tsx     → 引用 src/modules/dashboard
│
├── modules/                 # 业务模块（核心！）
│   ├── home/                # 首页模块
│   │   ├── ui/              # UI 层（仅展示）
│   │   │   ├── components/  # React 组件（可含 'use client'）
│   │   │   ├── layouts/     # 模块专属布局（如 HomeLayout）
│   │   │   └── styles/      # CSS Modules / Tailwind @layer
│   │   ├── api/             # 模块内 API 调用封装
│   │   ├── hooks/           # 自定义 Hooks（useHomeData 等）
│   │   ├── utils/           # 工具函数（formatDate, validate 等）
│   │   ├── constants/       # 常量（HOME_TITLE, MAX_ITEMS）
│   │   ├── types/           # TypeScript 类型定义
│   │   ├── lib/             # 模块内核心逻辑（非 UI）
│   │   └── index.ts         # 模块公共出口（ Barrel File ）
│   │
│   └── auth/                # 认证模块（示例）
│       ├── ...
│
├── shared/                  # 跨模块共享代码
│   ├── ui/                  # 全局组件（Button, Card, ThemeProvider）
│   ├── lib/                 # 全局工具（fetcher, logger）
│   ├── types/               # 全局类型（User, ApiResponse）
│   └── assets/              # 公共资源（icons, images）
│
├── lib/                     # 应用级底层库（可选）
└── types/                   # 全局类型声明（.d.ts）

    关键点：

    • app/ 只负责路由和页面组装，不包含业务逻辑
    • 所有业务逻辑、UI、数据获取都在 modules/ 中
    • 通过 index.ts 控制模块对外暴露的 API

  3. 模块出口文件（index.ts）示例

    // src/modules/home/index.ts

// 只导出需要被外部使用的部分
export { default as HomePage } from './ui/components/HomePage';
export { default as HomeLayout } from './ui/layouts/HomeLayout';
export { useHomeData } from './hooks/useHomeData';
export type { HomePost } from './types';
export { HOME_MAX_POSTS } from './constants';

    在页面中使用：

    // src/app/(marketing)/page.tsx
import { HomePage, useHomeData } from '@/modules/home';

export default function Home() {
  const { data } = useHomeData(); // 或直接在服务端 fetch
  return <HomePage posts={data} />;
}

    优势：

    • 外部无需知道模块内部结构
    • 重构内部文件不影响调用方
    • 支持 Tree Shaking（未使用的导出不会打包）

  4. Next.js 特性集成建议

    1. 服务端数据获取 → 放在 app/ 页面中

      虽然模块包含 api/，但 Next.js 要求数据获取在页面组件中进行（RSC 规范）：

      // src/app/(marketing)/page.tsx
import { fetchHomePosts } from '@/modules/home/api'; // 封装好的 fetch

export default async function Home() {
    const posts = await fetchHomePosts(); //  服务端执行
    return <HomePage posts={posts} />;
}

      modules/home/api/fetchHomePosts.ts 示例：

      export async function fetchHomePosts() {

}

  5. 模块间通信与依赖管理

    • 避免直接跨模块 import

      // BAD: 破坏模块边界

      正确做法：

      1. 公共逻辑 → 移入 shared/

      3. 状态共享 → 使用全局状态库（如 Zustand）或 Context（谨慎）

2.2.4 静态资源导入

在 Next.js（基于 App Router）中，资源导入（如图片、字体、CSS、JSON、Web Workers 等）已深度集成现代前端工程能力，并充分利用 React Server Components（RSC）、Turbopack（默认开发服务器） 和 Webpack 5 的特性，实现自动优化、类型安全、服务端/客户端无缝使用。

  1. 通用原则

    原则说明
    优先使用 next/ 工具如 next/image、next/font，自动优化
    静态资源放 public/ 或 src/public/ → 直接通过 /file 访问；src/ → 需 import
    服务端组件可直接 import 资源RSC 支持原生 ES Module 导入 JSON、图片等
    类型安全TypeScript + Next.js 内置类型支持

    推荐目录结构：

    src/
├── app/          # 路由
├── assets/       # 图片、字体、数据等（需 import）
└── public/       # 静态文件（favicon.ico, robots.txt）

  2. 各类资源导入详解

    1. 图片（Images）

      推荐：使用 next/image（自动优化）

      // src/app/page.tsx
import Image from 'next/image';
import heroImg from '@/assets/images/hero.jpg'; // 静态导入

export default function Home() {
  return (
    <Image
      src={heroImg}        //  类型安全，自动计算宽高
      alt="Hero"
      priority            // 首屏加载
      placeholder="blur"  // 模糊占位（需配置 blurDataURL）
    />
  );
}

      配置（可选）：next.config.ts

      // next.config.ts
const nextConfig = {
  images: {
    remotePatterns: [
      { hostname: 'cdn.example.com' }, // 允许外部图片
    ],
  },
};

      注意：

      • 本地图片必须通过 import 引入（不能用字符串路径）
      • public/ 下的图片可用字符串路径，但失去类型检查和自动尺寸：
        <Image src="/logo.png" width={100} height={100} alt="logo" />

    2. 字体（Fonts）

      推荐：使用 next/font（自动自托管 + 无布局偏移）

      // src/app/layout.tsx
import { Inter } from 'next/font/google';
import localFont from 'next/font/local';

const inter = Inter({ subsets: ['latin'] });
const myFont = localFont({ src: '../assets/fonts/my-font.woff2' });

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body className={`${inter.className} ${myFont.className}`}>
        {children}
      </body>
    </html>
  );
}

      优势：

      • 自动预加载
      • 无 FOIT/FOUT（字体加载时保持布局）
      • 打包时内联 WOFF2

    3. CSS / 样式

      • (1) 全局 CSS

        只能在 layout.tsx 或 page.tsx 中导入（App Router 限制）

        // src/app/layout.tsx
import '@/assets/styles/globals.css'; //  允许

export default function Layout({ children }: { children: React.ReactNode }) {
return <html><body>{children}</body></html>;
}

      • (2) CSS Modules

        // src/modules/home/ui/components/Card.module.css
.card { padding: 1rem; }

// src/modules/home/ui/components/Card.tsx
import styles from './Card.module.css';

export default function Card() {
return <div className={styles.card}>...</div>;
}

      • (3) Tailwind CSS

        • 直接使用 class，无需 import
        • 配置 tailwind.config.ts 即可

      • (4) CSS-in-JS（如 styled-components）

        • 不推荐（与 RSC 冲突）
        • 如需使用，组件必须标记 'use client'

    4. JSON 数据

      • 服务端组件直接 import（RSC 原生支持）
      // src/assets/data/config.json
{ "title": "My App" }

// src/app/layout.tsx
import config from '@/assets/data/config.json';

export const metadata = {
  title: config.title, // 安全！
};

      编译时 JSON 会被内联，不会发送到客户端（除非在客户端组件中使用）。

    5. Web Workers

      使用 new Worker() + ?worker 查询（需配置）

      // src/lib/workers/image-processor.worker.ts
self.onmessage = (e) => {
  // 处理逻辑
  self.postMessage(result);
};

// src/modules/editor/hooks/useImageProcessor.ts
'use client';

import Worker from '@/lib/workers/image-processor.worker?worker';

export function useImageProcessor() {
  const worker = new Worker();
  // ...
}

      注意：

      • 需在 next.config.ts 中启用 Webpack 的 worker 规则（Turbopack 原生支持）
      • Worker 文件必须是独立入口

    6. SVG 图标

      • 方案 1：作为 React 组件（推荐）

        // src/assets/icons/Logo.tsx
export default function Logo(props: React.SVGProps<SVGSVGElement>) {
return (
    <svg {...props} viewBox="0 0 24 24">
    <path d="..." />
    </svg>
);
}

// 使用
import Logo from '@/assets/icons/Logo';
<Logo width={32} height={32} />

      • 方案 2：作为静态资源

        import logoUrl from '@/assets/icons/logo.svg';
<img src={logoUrl} alt="logo" />

      优势：方案 1 支持动态 props、主题色；方案 2 适合复杂 SVG。

    7. 外部资源（CDN、第三方库）

      • (1) 脚本（如 Google Analytics）

        使用 next/script 控制加载时机：

        // src/app/layout.tsx
import Script from 'next/script';

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        {children}
        <Script
          src="https://www.googletagmanager.com/gtag/js?id=G-XXXX"
          strategy="afterInteractive"
        />
      </body>
    </html>
  );
}

      • (2) 第三方 NPM 包

        • 直接 import（如 lodash, date-fns）
        • 注意：若包含 DOM 操作，只能在 'use client' 组件中使用

  3. 资源优化最佳实践

    资源类型优化建议
    图片用 next/image + WebP/AVIF + priority/loading="lazy"
    字体用 next/font + display: swap
    CSS用 Tailwind + PurgeCSS（自动 Tree Shaking）
    JS利用代码分割（每个页面/模块独立 chunk）
    数据服务端 fetch + cache/revalidate 控制

  4. 常见错误与解决方案

    错误原因解决
    Module not found: Can't resolve './image.png'图片未正确 import改为 import img from './image.png'
    Global CSS can only be imported in layout or page在组件中 import 全局 CSS改用 CSS Modules 或移到 layout
    window is not defined在服务端组件使用浏览器 API标记 'use client' 或用 useEffect
    Worker is not a constructor未正确配置 Worker使用 ?worker 后缀或检查 bundler 配置
