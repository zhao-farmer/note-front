  3. 目录结构解释

    my-nuxt-app/
├── app/              # 应用核心代码（Nuxt 4 新增）
│   ├── assest/       # 静态资源（文件中直接使用）
│   ├── components/   # 自动导入的 Vue 组件
│   ├── pages/        # 文件系统路由（自动生成）
│   ├── layouts/      # 页面布局组件
│   ├── composables/  # Composition API 逻辑
│   ├── middleware/   # 路由中间件
│   ├── plugins/      # 客户端插件
│   ├── stores/       # 状态管理（如 Pinia）
│   └── app.vue       # 应用根组件
├── server/           # 服务端代码（Nitro）
├── shared/           # 前后端共享代码（类型、工具）
├── public/           # 静态资源（直接映射到根路径）
└── nuxt.config.ts    # 主配置文件（TypeScript 格式）

  4. 静态资源引用

    • assets 资源的引用: ~ 或 @

// CSS
background-image: url(~assets/13.jpg);
background-image: url(~/assets/13.jpg);
background-image: url(@/assets/13.jpg);

    • public 目录资源的引用: / 直接引用

3.3 路由结构

  1. 路由概述

    Nuxt.js 依据 pages 目录结构自动生成 vue-router 模块的路由配置。

    要在页面之间切换路由, 使用 <nuxt-link> 标签。

    标签名描述
    <nuxt-link>nuxt.js 中切换路由
    <NuxtPage />nuxt.js 的路由视图

  2. 静态路由

    • 自动生成基础路由规则--静态路由

      路径组件位置及其名称规则
      /app/pages/index.vue默认文件 index.vue
      /userapp/pages/user/index.vue默认文件 index.vue
      /user/oneapp/pages/user/one.vue指定文件

    • 实例

      1. 情况1：访问路径，由pages目录资源的名称组成（目录名称、文件的名称）
        • 资源位置： app/pages/user/one.vue
        • 访问路径：http://localhost:3000/user/one
      2. 情况2：每一个目录下，都有一个默认文件 index.vue
        • 资源位置： app/pages/user/index.vue
        • 访问路径：http://localhost:3000/user
      3. /user 可以匹配几种文件?
        • pages/user.vue (优先级高)
        • pages/user/index.vue 文件

  3. 动态路由

    • 介绍

      如果您在文件名中使用方括号 [ ]，它将被转换为 动态路由 参数。您可以在文件名或目录中混合使用多个参数，甚至是非动态文本。

      如果您希望参数是 可选的，必须使用双括号 [[]] 括起来，例如 ~/pages/[[slug]]/index.vue 或 ~/pages/[[slug]].vue 将匹配 / 。

    • 示例

      • 目录结构

        -| pages/
---| index.vue
---| users-[group]/
-----| [id].vue

      • pages/users-[group]/[id].vue

        <template>
    <p>{{ $route.params.group }} - {{ $route.params.id }}</p>
</template>

      • 路由 /users-admins/123 将渲染：

        <p>admins - 123</p>

  4. 嵌套路由

    • 介绍

      可以使用 <NuxtPage> 显示 嵌套路由。

    • 示例

      • 目录结构

        -| pages/
---| parent/
-----| child.vue
---| parent.vue

      • 文件树将生成以下路由：

        [
    {
        path: '/parent',
        component: '~/pages/parent.vue',
        name: 'parent',
        children: [
            {
                path: 'child',
                component: '~/pages/parent/child.vue',
                name: 'parent-child'
            }
        ]
    }
]

      • 要显示 child.vue 组件，您需要在 pages/parent.vue 中插入 <NuxtPage> 组件：

        • pages/parent.vue

          <template>
<div>
    <h1>我是父视图</h1>
    <NuxtPage :foobar="123" />
</div>
</template>

        • pages/parent/child.vue

          <script setup lang="ts">
const props = defineProps(['foobar'])

console.log(props.foobar)
</script>

  5. 自定义路由

    • 通过 router.options 扩展‌

      在 app/router.options.ts 中直接覆盖或扩展路由配置，支持 TypeScript 类型推断

      import type { RouterConfig } from '@nuxt/schema'
export default {
    routes: (defaultRoutes) => [
        ...defaultRoutes,
        { path: '/custom', component: () => import('~/pages/custom.vue') }
    ]
} satisfies RouterConfig

    • 使用 pages:extend 钩子‌

      在 nuxt.config.ts 中动态修改路由表，适合批量操作

      export default defineNuxtConfig({
    hooks: {
        'pages:extend'(pages) {
            pages.push({ name: 'admin', path: '/admin', file: '~/pages/admin.vue' })
        }
    }
})

    • 基础路径与分隔符‌

      • base‌：设置应用根路径（如部署在子目录时）

        export default defineNuxtConfig({
    router: { base: '/my-app/' }
})

      • routeNameSplitter‌：修改路由名称分隔符（默认 -）

        export default defineNuxtConfig({
    router: { routeNameSplitter: '/' }
})

3.4 路由中间件

  1. 介绍

    Nuxt中提供了一个路由中间件，它允许在路由跳转前或者路由跳转后执行一些代码，例如进行页面访问权限的验证、记录用户的访问记录等等。我们可以在项目根目录下创建middleware/目录来放我们创建的中间件。

    路由中间件的类型

    • 命名路由中间件

      放置在middleware/中，在页面上使用时会通过异步导入自动加载

    • 匿名(或内联)路由中间件

      直接在使用的页面中定义

    • 全局路由中间件

      放置在 middleware/中(带有.global后缀)，并将在每次路由更改时自动运行。

  2. 目录结构

    src/
├── middleware/
│   ├── auth.global.ts      ← 全局中间件（所有路由）
│   └── admin.ts            ← 命名中间件（仅指定页面使用）
├── pages/
│   ├── login.vue           ← 用于跳转的登录页
│   └── dashboard.vue       ← 主页（含匿名路由）

  3. 示例代码

    • 全局路由中间件

      // auth.global.ts
export default defineNuxtRouteMiddleware((to, from) => {
  const { isAuthenticated } = useAuth(); // 假设你有 auth composable

  // 跳过不需要认证的页面
  const publicPages = ['/', '/login', '/about'];
  if (publicPages.includes(to.path)) {
    return;
  }

  // 未认证 → 重定向到登录页
  if (!isAuthenticated.value) {
    return navigateTo('/login');
  }
});

    • 命名中间件

      // admin.ts
export default defineNuxtRouteMiddleware(async (to) => {
  const user = await getCurrentUser(); // 异步获取用户

  if (user?.role !== 'admin') {
    return abortNavigation('无权访问'); // 或 navigateTo('/403')
  }
});

      <!-- dashboard.vue -->
<script setup>
    definePageMeta({
        middleware: 'auth'  // 使用中间件auth.js
    });
</script>

    • 匿名路由

      <!-- dashboard.vue -->
<script setup>
    definePageMeta({
        middleware: defineNuxtRouteMiddleware((to, from) => {
            let user = true;
            if(!user){  
                return navigateTo('/login'); 
            }
        })
    });
</script>

3.5 插件Plugins

  1. 介绍

    在Nuxt中，插件是一种在构建时注册和使用的模块，可以用于处理常规的」avaScript依赖和特殊的框架配 置，同时也可以与Nuxt项目一起发布。

    类型位置执行时机注册方式使用场景
    客户端插件​plugins/目录客户端加载时.client.ts后缀浏览器API、第三方 SDK
    服务端插件​plugins/目录服务端启动时.server.ts后缀数据库连接、服务初始 化
    通用插件​plugins/目录两端都执行无特殊后缀工具函数、Vue插件

  2. 插件目录结构

    src/
└── plugins/
    ├── axios.ts            ← 自定义插件
    ├── i18n.client.ts      ← 仅客户端运行
    └── logger.server.ts    ← 仅服务端运行
    • 所有 .ts/.js 文件会 自动注册，无需手动引入
    • 文件名后缀 .client / .server 控制运行环境

  3. 代码示例

    • 新建axios插件

      // plugins/axios.ts
import { defineNuxtPlugin } from '#app';
import axios from 'axios';

export default defineNuxtPlugin((nuxtApp) => {
  const api = axios.create({
    baseURL: process.env.API_BASE_URL || 'https://api.example.com',
    timeout: 10000
  });

  // 请求拦截器
  api.interceptors.request.use(config => {
    const token = useCookie('token').value;
    if (token) config.headers.Authorization = `Bearer ${token}`;
    return config;
  });

  // 响应拦截器
  api.interceptors.response.use(
    response => response,
    error => {
      if (error.response?.status === 401) {
        navigateTo('/login');
      }
      return Promise.reject(error);
    }
  );

  return {
    provide: {
      axios: api
    }
  };
});

    • 在组件中使用

      <script setup>
    const { $axios } = useNuxtApp();

    // 或直接 auto-import（推荐）
    // 需在 nuxt.config.ts 中启用 autoImports
</script>

3.7 组合式函数 Composables

  1. 常用内置函数

    Composable用途
    useState跨 SSR/CSR 共享状态
    useCookie读写 Cookie（全栈安全）
    useFetch发起 HTTP 请求（SSR 预渲染）
    useAsyncData异步数据加载（带缓存）
    useRouter访问 Vue Router
    useRuntimeConfig访问运行时配置（如 API 密钥）
    useRequestEvent获取 Nitro 请求事件（仅服务端）

  2. useState —— 跨 SSR/CSR 共享响应式状态

    用途：在服务端和客户端之间同步状态，避免 hydration mismatch。

    示例：全局加载状态

    // composables/useLoading.ts
export const useLoading = () => {
  // key 必须唯一，推荐加命名空间
  const loading = useState('global/loading', () => false);

  const start = () => loading.value = true;
  const finish = () => loading.value = false;

  return { loading, start, finish };
};

    在页面中使用：

    <script setup>
const { loading } = useLoading();
</script>

<template>
  <div v-if="loading">加载中...</div>
  <Content v-else />
</template>

    注意：不要在 useState 初始化函数中访问 window 或 localStorage（SSR 不可 用）。

  3. useCookie —— 全栈安全地读写 Cookie

    用途：统一处理 Cookie，自动适配 SSR（通过 Nitro event）和 CSR（通过 document.cookie）。

    示例：保存用户语言偏好

    // composables/useLocale.ts
export const useLocale = () => {
  const locale = useCookie('locale', {
    maxAge: 60 * 60 * 24 * 30, // 30 天
    default: () => 'zh-CN',
    path: '/'
  });

  const setLocale = (lang: string) => {
    locale.value = lang;
    // 可选：触发 i18n 切换
  };

  return { locale, setLocale };
};

    在 App.vue 中初始化：

    <script setup>
const { locale } = useLocale();
// 自动从 Cookie 读取，SSR 渲染时已生效
</script>

    安全提示：敏感数据（如 refresh token）应设 httpOnly: true，但此时前端无法读取！

  4. useFetch —— 发起 HTTP 请求（SSR 预渲染）

    用途：替代原生 fetch，自动在 SSR 时预取数据，客户端激活后复用。

    示例：获取用户信息

    // pages/profile.vue
<script setup>
// 自动在 SSR 时请求，HTML 中已包含数据
const { data: user, pending, error } = await useFetch('/api/user');

// 或带选项
// const { data } = await useFetch('/api/user', {
//   headers: { Authorization: `Bearer ${token}` }
// });
</script>

<template>
  <div v-if="pending">加载中...</div>
  <div v-else-if="error">加载失败</div>
  <div v-else>
    欢迎, {{ user?.name }}!
  </div>
</template>

    💡 优势：

    • 自动序列化响应（无需 .json()）
    • SSR 时走服务端代理（避免 CORS）
    • 客户端缓存（相同 URL 不重复请求）

  5. useAsyncData —— 异步数据加载（更灵活）

    用途：比 useFetch 更通用，可执行任意异步逻辑（如调用 SDK、组合多个 API）。

    示例：获取商品 + 库存

    // pages/product/[id].vue
<script setup>
const route = useRoute();

const { data: product } = await useAsyncData(
  `product-${route.params.id}`, // 唯一 key（用于缓存）
  async () => {
    const [product, stock] = await Promise.all([
      $fetch(`/api/products/${route.params.id}`),
      $fetch(`/api/stock/${route.params.id}`)
    ]);
    return { ...product, stock: stock.count };
  }
);
</script>

    🔁 与 useFetch 对比：

    • useFetch(url) → 专用于简单 HTTP 请求
    • useAsyncData(key, handler) → 适用于复杂异步逻辑

  6. useRouter —— 访问 Vue Router

    用途：编程式导航、监听路由变化。

    示例：登录后跳转回原页面

    // composables/useAuthRedirect.ts
export const useAuthRedirect = () => {
  const router = useRouter();
  const route = useRoute();

  const loginAndRedirect = async () => {
    await login(); // 假设这是登录函数
    // 跳转回来源页面，或默认首页
    const redirect = route.query.redirect as string || '/';
    await router.push(redirect);
  };

  return { loginAndRedirect };
};

    在登录页使用：

    <script setup>
const { loginAndRedirect } = useAuthRedirect();
</script>

<template>
  <button @click="loginAndRedirect">登录</button>
</template>

    注意：useRouter().push() 在 SSR 中不会真正跳转，仅在客户端生效。

  7. useRuntimeConfig —— 安全访问配置

    用途：读取运行时配置（如 API 地址、第三方密钥），区分 public/private。

    配置：

    // nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    // 私有配置（仅服务端可用）
    apiSecret: process.env.API_SECRET,
    // 公共配置（客户端+服务端）
    public: {
      apiBase: process.env.NUXT_PUBLIC_API_BASE || '/api'
    }
  }
});

    使用：

    // composables/useApi.ts
export const useApi = () => {
  const config = useRuntimeConfig();

  // 仅服务端可访问 config.apiSecret
  const privateToken = config.apiSecret; 

  // 客户端可访问 config.public.apiBase
  return $fetch.create({
    baseURL: config.public.apiBase
  });
};

    安全原则：

    • 敏感数据（密码、密钥）放 runtimeConfig 根层级 → 仅服务端可见
    • 公共数据（API 域名）放 runtimeConfig.public → 客户端可见

  8. useRequestEvent —— 获取 Nitro 请求上下文（仅服务端）

    用途：在 SSR 期间访问原始请求对象（如 headers、IP、cookies）。

    示例：根据 User-Agent 返回不同内容

    // plugins/detect-bot.ts
export default defineNuxtPlugin(async (nuxtApp) => {
  if (process.server) {
    const event = useRequestEvent(nuxtApp);
    const userAgent = event?.node.req.headers['user-agent'] || '';

    if (userAgent.includes('bot') || userAgent.includes('crawler')) {
      // 可注入特殊 meta 标签等
      useState('isBot', () => true);
    }
  }
});

    在页面中使用：

    <script setup>
const isBot = useState('isBot', () => false);
</script>

<template>
  <div v-if="isBot">搜索引擎看到的内容</div>
  <div v-else>普通用户看到的内容</div>
</template>

    限制：仅在 服务端 有效，客户端调用返回 undefined。
